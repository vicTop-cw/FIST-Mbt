
## R70 `fix/whisperer-selftest-and-scan-gitdir`（agent-skill-docs）—— 风语者自检在 worktree 里恒红：根因不在它自己

- 上手先跑 master 上最新的 `whisperer.py --self-test`（TASK-009，别的线刚落的件）⇒ **rc=2**，
  红在 `G1 fist-gate.py --scan rc=1`。**一个工具的自检在它自己的仓库里就是红的**，这条线显然没被在
  worktree 里跑过。
- 根因（三层，逐层剥）：① `fist-gate.py --scan` 原实现用 `Path(root)/".git"/"fist"/...` 建输出目录，
  而**在 git worktree 里 `.git` 是文件**（gitdir 指针）⇒ `FileNotFoundError`；② 未捕获异常让退出码
  变成 1，于是下游把它读成"判据红了"（**异常退 1 冒充判据红**，与 BUG-303 同族的坑）；③ whisperer 的 G1
  只印 `rc=N` 不说原因，且 `run()` 不传 `cwd` ⇒ 在别的目录跑自检还会"找不到 scripts/fist-gate.py"，
  两件事叠在一起，红得没有信息量。
- 修法：`fist-gate.py` 改用 `git rev-parse --absolute-git-dir`（取不到 rc=2 拒绝"在错位置写任务"）；
  whisperer G1 固定 `cwd=ROOT`、并把结果分**三档**：绿 / **DEGRADED(rc=2) 单列** / 红带末行+提示
  （DEGRADED 既不是绿也不是"你坏了"——把它算绿会掩盖下游故障，算红会让人去翻本脚本的源码）。
- 顺带统一旗标：本工具只认 `--self-test`，而全仓惯例是 `--selftest` ⇒ 任何"对所有尺统一跑 --selftest"
  的自动化都会在它身上拿到 argparse rc=2。现两个都收（同一 dest），行为一致。
- 签收：`--self-test`/`--selftest` 均 **rc=2 → 0**；`fist-gate.py --scan` 在 worktree 里 **rc=0** 且 yaml
  落到真实 gitdir；从 `C:\` 跑 whisperer 自检仍 **rc=0**（证明 ROOT 修正真的生效，不是碰巧）。
- 方法论沉淀：**"自检红"必须先分清「我没量到」「下游坏了」「我坏了」三档**。只印一个 rc 的做法会让
  读者把三种混成一类，最后就是没人读红——本项目反复出现的那条主线。


## R76 `fix/mbti-generic-fn`（lead-2）—— 判据盲区：泛型顶层 fn 让"丢件"隐形（BUG-381 → PR #16）

- **盲区实测**（不是推断）：`check_mbti_sync` 的 `SHAPES["fn"]` 两侧正则都要求 `fn` 后**有空格再接名字**；
  泛型顶层写法 `pub fn[T : @rhop.RhopCipher] rhop_poll_once(...)` 里 `[` 紧跟 `fn` ⇒ 两侧 `\w+` 全失配。
  对声明行与定义行单独跑正则均返回 None（本轮实测）。
- **代价**：master 上该尺报 `PASS … 675 条 pub 声明全有定义`，而 `rhop_poll_once` 在 `src/**` 零定义——
  **假绿**；本轮三臂 CI 恒红在 Migrate 的编译回归，正是从这道门底下溜过去的。
- **修法**：两侧放宽为可选 `[...]` 段；`--selftest` 增三格（泛型声明入集 / 泛型定义入集 / 悬空泛型声明必红，
  三格在旧正则下必红 ⇒ 变异自证）；汇总自述同步补这三格（J10 判据范围自述==实现）。
- **两向验证**：master 上 rc=1 且**精确点名** `src/ops/pkg.generated.mbti` 的 `rhop_poll_once`（675→676 条，
  多出的正是那条隐形声明）；在含实现的分支上 rc=0、676 条零误报。自检 20 格全绿。
- **限制如实标注**：只认单行类型参数列表；`pub fn[\n T : Foo,\n] name` 跨行写法仍需改跨行状态机
  （本仓无此形态）——写进代码注释，免得下一步又踩同样的隐形。
- **教训**：① 「判据 PASS」有时只是**判据看不见**——凡是被正则形状驱动的守卫，都要问"哪些写法不进我的宇宙"；
  ② 盲区的杀伤力与它罩住的符号数成正比：全仓仅 1 个泛型顶层 fn，恰好就是丢件主角，这种巧合不是运气，是
  **盲区越窄、命中就越是致命的单点**；③ 修判据必须成对给出「能红」与「不误红」两向读数，否则只是把盲区
  换成了误报。

- **同轮另一发现（竞争性修复）**：并行 lane 在 gitcode/main 落 `0279c63e`，用**删孤儿测试文件**的方式消同一
  编译红，理由「依赖未暴露解码 API ⇒ 无法实现」。**理由不成立**：实现就在本仓历史里（`e912d1b3`，报告实测
  1340/1340 绿），PR #12 是逐字节还原。已在 PR #12 贴对照表并写明「两案都合时必须把测试文件加回」的收口要求。
  —— 教训：**"无法实现"是强断言，必须先去历史里找一遍**；删测试消红会让能力静默下线，比红着更贵。
