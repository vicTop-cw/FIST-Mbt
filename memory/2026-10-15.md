# Round 117 · BUG-157 修复独立验证 + 单主跨进程回归判据（金条五）

**日期**：2026-10-15　**HEAD**：`9cb51bc`

## 做了什么

**只读终审并发 agent 的 BUG-157 修复**：它在 `src/store/store_sqlite.mbt` L1646-1667 的 `assistant_upsert` 加了清场 UPDATE（`UPDATE assistant_reg SET is_primary=0 WHERE is_primary=1 AND agent != ?`）+ 原有 ON CONFLICT upsert。我逐字读了完整函数体。

**关键发现——修复非原子（TOCTOU）**：清场 UPDATE 与 upsert INSERT 是**两条独立语句、无 `BEGIN IMMEDIATE` 事务包裹**。SQLite autocommit 下理论竞态：两进程都读到无人主 → 都 no-op 清场 → 都写 is_primary=1（原 BUG-157 5 进程全 elected 的变体）。

**写独立跨进程判据验证**：`scripts/blackbox/e2e_assistant_xproc.py`——用 Python `sqlite3` 逐字复刻其 SQL 形态，起 N 进程 `spawn` 在 `threading.Barrier` 同闸抢主跑多轮，任一轮 >1 行 `is_primary=1` 即 FAIL。`--atomic` 模式用 `BEGIN IMMEDIATE` 包临界区作可证明原子对照。

## 实测结果

| 形态 | 参数 | 结果 |
|---|---|---|
| 当前修复（无事务） | 5 进程 × 20 轮 | 20/20 单主成立 |
| 当前修复（无事务） | 8 进程 × 40 轮 | 40/40 单主成立 |
| 当前修复（无事务） | 8 进程 × 60 轮 | 60/60 单主成立 |
| `--atomic`（BEGIN IMMEDIATE） | 8 进程 × 40 轮 | 40/40 单主成立 |

**结论**：**BUG-157 修复实测有效但非可证明原子**。理论 TOCTOU 窗口存在，但 SQLite 文件级写串行化 + UPDATE→INSERT 紧邻使窗口实际不击穿（60/60 最高压力仍单主）。`BEGIN IMMEDIATE` 是强化项非必需。

## 提交

## 可复用教训

1. **"先清场再写"两语句不等于原子**：没有 `BEGIN IMMEDIATE` 就是 TOCTOU。判据必须能造出"两进程同时读到无人主"窗口（起多进程 + Barrier 同闸），单进程（哪怕真 SQLite）结构上造不出来。
