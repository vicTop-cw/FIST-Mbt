### 一、凭据：不做「删变量当撤销」这个假动作

- **为什么不删**：删 `HKCU\Environment\FIST_GITHUB_TOKEN` 既**不会让令牌失效**（吊销要在 GitHub 侧做，那是外部共享系统，
  我没有这个权限也不该代持），又可能把 owner 手上**唯一一份副本**弄没 ⇒ 假安全感 + 真损失。
- **实际做的**：把本仓自带的软开关翻下去——`FIST_GITHUB_ENABLED` 由 `true` 改为 **`false`**，并广播 `WM_SETTINGCHANGE`。
  读数是现取的：注册表面 `reg query` 回读 = `false`；会话进程面（旧 env 的继承）= `true`；
  **连接器服务面**（真正会外发 issue 的那一侧）在动手前后都是 `github_env_check` 的
  `{"enabled":false, "token_present":false, "ready":false}` ⇒ 这台机器今天本来就没有自动外发能力，
  这次翻转是把"注册表说 true、调用面说 false"这种两面不一致消掉，而不是制造限制。
- **外发面本来就空**：`memory/*github*.jsonl` 队列文件不存在（0 条待同步）⇒ 翻转不损失任何在途内容。
- **明文暴露审计**（`temp/b136_credential_audit.py`，只报路径与次数、永不回显值；令牌也不进任何 argv，
  全历史用 `git cat-file --batch-all-objects --batch` 流式比对）：
  工作树 **11806** 个文件命中 0；全历史 **6824** 个对象（blob 3064）命中 0；临时目录里 curl 认证件 0 件
