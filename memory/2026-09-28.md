## 学到 / 下次直接按这条办

- **"验证各功能可用"不能靠手写清单**：参数必须从被验对象的 `inputSchema` 反解；手写 129 条会把自己的
  键名错（`laya_decide` 收窄、`report_bug` 的 `summary`）报成"产品拒绝"。
- **进程死了不能把后续全记 broken**：要分诊 + 复活 + 继续数，并且结论行必须带**基数自证**
  （`len(rows) != len(tools)` 直接 rc=2）。本轮第一版就是"kinds 数到 129、rows 只存了 6 行"，
  结论照样打了 GREEN——明细丢了，拒绝文案再也举不出来。
- **文件位置的断言 ≠ 存储隔离的断言**：`scratch_verify.py` 只查"仓库根没有 `{ns}.db` 这个文件"，
  从不查行落点，于是恒绿了几个月。以后凡是"隔离/落盘"类判据，**必须数被写入的行**。
- **同一份共享库上的判据不可用**：仓库根 `fist-mbt.db` 是多轮共用面，任何一格依赖它都会被别人写脏；
  巡回与探针一律 `FIST_DB_PATH` 指独立库，读面也只读源码不读共享账。

## 补遗 · 以用户身份用 bash 敲了一下 `fist`（BUG-105 / BUG-106）（盖章 2026-09-28T07:51:57Z）

`fist doctor` 在 PowerShell 里 5/5，在 Git Bash 里 `fist` 这个命令根本不存在——同一个安装、同一个人，
两半结论相反。根因不在产品，在 **shim 只有一种扩展名**：POSIX shell 不解析 PATHEXT。

- 修（BUG-105，入账即 FIXED）：Windows 安装器再写一份无扩展名 `#!/bin/sh` shim（**LF**，
  CRLF 的 shebang 在 bash 里是 `bad interpreter`，装完当场看不出来），并加两道门：
  四件不齐 ⇒ 点名 + `exit 1`；shebang 不对或含 CR ⇒ `exit 1`。
- 判据（R5 进 `check_release_asset_names.py`，六格 ⇒ 八格），门自己配负面向对照
  （`temp/b105_gate_canary.py`：摘掉写入必红、原样必绿）——"四件门"如果从来没红过，
  它可能只是恰好四件都在。
- 调用面证据：隔离 bin 里 `fist version`→v0.3.0、`fist doctor`→5/5；真机 `~/.local/bin` 只新增两个
  无扩展名文件，没碰并行改动面装好的 `.cmd` 与 `fist-mbt.js`。

新开一条 **BUG-106（OPEN，交并行改动面）**：`fist --help/-h/--version/-V` 全被判"未知子命令"，
而未知子命令回 **exit 0** ⇒ 包装脚本会把失败读成成功。没在本环动手的理由写在账本里，
