## call_log 缺陷诊断与修复（fist-mbt 自驱闭环）— 完成

- **根因（call_log 全库 453/453 损坏）**：`@env.now()` 返回 UInt64 毫秒，[server.mbt](server.mbt) 的 `now_default`/`_instrument` 用 `.to_int()` 对 UInt64 做 **32 位截断**（`1790319218428 → -682144004`）→ 全部内部时间戳变 1969、seq 为负，破坏心跳/陈旧检测/审计与多项目排序。
- **修复**：
  1. `now_default()` 改用 `.to_int64()` 做 Int64 运算，产出真实 `YYYY-MM-DDTHH:MM:SSZ`；
  2. `seq` 改用进程内单调计数器 `_call_log_seq`，[store_sqlite.mbt](../src/store/store_sqlite.mbt) `recent_call_logs` 改 `ORDER BY id DESC`；
  3. [call_log_wbtest.mbt](call_log_wbtest.mbt) 改独立内存引擎，消除对共享 `fist-mbt.db` 的测试污染；清洗 464 条损坏 + 8 条 `wbtool_err` 假行；
  4. `_log_call` 增加 ns 缺失回退 `project_dir`，实现兄弟项目可追分组。
- **验证**：`moon test --target js` **191/191 全绿**；清洗后库 162 条全为 2026 合法 ts、0 损坏 0 污染；`cron-cypy` 兄弟项目新日志同步变干净。
