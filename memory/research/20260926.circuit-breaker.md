# 调研档：熔断器 circuit_breaker（R104 候选 · 2026-09-26）

> 来源（WebSearch 实检）：Michael Nygard《Release It!》（2007/2018，熔断器模式首倡）；Martin Fowler「CircuitBreaker」（martinfowler.com/bliki）；Microsoft Azure Architecture Center「Circuit Breaker pattern」；AWS Prescriptive Guidance「Circuit breaker pattern」；Molchanov/Zhmaiev 2018（微服务熔断综述）；BEE-12001（三态状态机 + 滑动窗口）。
> 前置：R90 phi_accrual（概率判活）、R92-R102 Saga 家族、health_check 四金信号。本档为 BACKLOG P2「Circuit Breaker 三态：Closed/Open/Half-Open 对外部调用快速失败」。

## 一、核心矛盾（为什么需要熔断）
- 分布式环境里对外部服务/资源调用失败可能是**长时故障**（非瞬态）：服务过载、崩溃循环、DB 不可用。持续重试 → 上游线程池/连接池耗尽 → **级联失败**（一个服务拖垮整条调用链）。
- 现状：fist-mbt 的 `heal`/`phi_accrual` 判"任务是否卡死"，Saga 管"补偿收尾"，但**对外部调用（run_check 的命令、HTTP 桥、Laya sidecar 等）没有"快速失败 + 恢复探测"**——失败时无状态机护栏。
- Circuit Breaker 解决：失败超阈值 → Open（fail-fast，微秒级返回，不耗线程池）；恢复定时器到期 → Half-Open（放少量探测请求）；探测成功 → Closed；失败 → 回 Open。

## 二、拿来主义落地（fist-mbt 版蒸馏）
| 外部信号 | fist-mbt 落地设计 |
|---|---|
| Closed/Open/Half-Open 三态状态机（Nygard/Fowler） | 新原语 `circuit_breaker`：外部调用前先查熔断状态（Closed 放行 / Open 立即拒绝 fail-fast / Half-Open 放行探测） |
| 滑动窗口失败率阈值（BEE-12001/Azure） | 窗口内失败计数（可配阈值，默认 3 次/窗口 60s）；4xx 类"调用方错误"不熔断（贴 Azure 原则：敏感于故障类型） |
| 恢复定时器 + 探测（AWS/Azure） | Open 后 recovery_secs 到期转 Half-Open；探测成功（连续 1 次）转 Closed |
| 幂等/持久化（与 reserve/executor 同模式） | 熔断状态表（双后端：内存 + SQLite `circuit_breakers` 表），`clear()` 一并清空 |

## 三、设计要点（复用避免造轮子）
- **API 语义**（编排中间层，不真调外部服务）：
  - `circuit_open(ns, circuit, failure, window_secs?, threshold?, recovery_secs?, now)`——上报一次失败并推进状态机（Closed 失败计数达阈值 → Open；Half-Open 探测失败 → Open 重启定时器）；返回状态；
  - `circuit_probe(ns, circuit, ok, now)`——外部调用结果回灌：ok=true 时（Closed 复位计数 / Half-Open → Closed）、ok=false 时（Closed 计数 / Half-Open 回 Open）；
  - `circuit_status(ns, circuit, now)`——查询状态（含 Half-Open 到期判断：now ≥ opened_at + recovery_secs → Half-Open 并可探测）。
- **复用**：store 双后端模式照 reserve/executor/saga（R10/R31/R92）；`clear()` 清空对齐 R11 纪律；失败窗口用时间戳毫秒/秒比较（iso_to_secs）。
- **零回归**：新工具独立注册（98→99），不改 heal/phi_accrual/watchdog 既有语义。

## 四、验证草案
- 单测：Closed 失败 2/3 次仍 Closed、第 3 次 → Open（fail-fast 拒绝）/ Half-Open 探测成功 → Closed / 探测失败 → 回 Open / 窗口外失败复位 / 幂等 / clear 清空。
- E2E：award_demo 加 R104 段（open→fail-fast→recovery→probe→closed 全环）；守卫族 + cleanup CLEAN。
