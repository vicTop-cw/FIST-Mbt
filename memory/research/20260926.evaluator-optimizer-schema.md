# 调研：Evaluator-Optimizer schema（feedback 收敛为 Defects/Evidence/Fix/Acceptance 四段式）— R111

> 日期 2026-09-26 · 来源：five-directions/§一「自计划 | Evaluator-Optimizer schema：feedback 收敛为 Defects/Evidence/Fix/Acceptance 四段式 | zubi.ai | ops_selfdrive.mbt | P2 | pending」
> 目的：给 fist-mbt 的"验收/反馈"环节加结构化 E/O 收敛——任何执行反馈先归一为四段式（Defects/Evidence/Fix/Acceptance），
> 由确定性规则判 verdict（有缺陷→fail 需优化；无缺陷→pass 可收敛），把"反馈驱动修订 plan_revise"升级为"结构化可计算反馈"。

## 一、核心锚点

### 1. Evaluator-Optimizer 工作流模式 — Anthropic《Building Effective Agents》+ 2026《Harness design for long-running application development》
- **E/O 模式**：Generator 产出 → Evaluator 按显式标准批判 → 反馈回灌 Generator 修订 → 直到质量阈值或迭代上限。生成与评估是**两种不同认知任务**，分离让各自专精。
- **关键实证（2026 harness）**：*"agents reliably skew positive when grading their own work"*——agent 自评倾向自夸；**分离"干活者"与"评判者"是强杠杆**。E/O 的价值在于"第二双眼睛"（evaluator 把草稿当输入读，不受生成时已承诺的框架束缚）。
- 终止条件 = quality gate：Evaluator 返回 PASS 即收敛（无缺陷）；返回 FAIL + 具体缺陷则回灌修订（硬上限防烧钱）。

### 2. Self-Refine — Madaan et al., arXiv 2303.17651 (2023)
- 单一模型循环：**Generate → Feedback → Refine**——模型给自己反馈并自我修正，迭代提升输出质量。
- 四段式反馈结构的近亲：反馈须**具体、可定位**（点名缺陷 + 证据），而非"整体还行"——泛化好评无法驱动优化。

### 3. Reflexion — Shinn et al., arXiv 2303.11366 (2023)
- 行动后把**失败经验**回写为反思记忆（verbal reinforcement），下一轮行动前注入——"踩过的坑"沉淀。
- 与本项目 evolve_lesson（失败回流 lesson）同族；四段式 feedback 的 Evidence 段即"回写什么"的原料。

### 4. zubi.ai 四段式（Defects/Evidence/Fix/Acceptance）— 直接需求来源
- **Defects**：本轮成果的缺陷清单（每个缺陷可独立定位）
- **Evidence**：支撑缺陷判定的证据/出处（可复现性——"凭什么说它错"）
- **Fix**：针对每个缺陷的定向修复建议（optimizer 的下手点）
- **Acceptance**：收敛判定标准（verdict 的量化门槛——"怎么算修好了"）
- 四段式把反馈从"叙事"变成"可计算契约"：缺陷数=0 且 acceptance 全满足 → pass；否则 fail + 定向回灌。

## 二、设计映射（四段式 → fist-mbt 反馈收敛）

| 段 | fist-mbt 实现 | 判定语义 |
|---|---|---|
| Defects | 从反馈文本解析 `## Defects` 段（每行一缺陷，- 列表） | 缺陷数 = 0 且 acceptance 非空满足 → pass |
| Evidence | 解析 `## Evidence` 段（证据列表） | 证据非空 = 缺陷可复现；缺陷 >0 但证据空 → 标记"证据不足"（仍 fail） |
| Fix | 解析 `## Fix` 段（修复建议列表） | 回灌 plan_revise rework 的下手点；缺陷 >0 但 fix 空 → 标记"修复缺失" |
| Acceptance | 解析 `## Acceptance` 段（验收标准列表） | 全满足（由调用方判定）→ 可收敛；与 Ω verify 的验收语义衔接 |

**核心语义**：`eval_feedback(feedback)` 纯读不写库——把自由文本反馈**归一为四段式 schema** + 确定性 verdict：
- 无缺陷 → verdict=pass（optimizer 可收敛，接受当前成果）
- 有缺陷（或四段不完整）→ verdict=fail + 四段式结构化输出（optimizer 按 Fix 定向修订 → 再 eval 循环，硬上限防死循环）

## 三、落地清单

5. 联动叙事：plan_revise（keep/rework/ready 三分）→ **eval_feedback（四段式收敛 + verdict）**——"反馈"从叙事变成可计算契约，E/O 闭环（defects→fix→再 eval→pass）在 AI 项目管理里落地。

## 四、风险与边界
- 纯读归一化工具：不改变既有 execute/submit/verify 行为（零回归）；"修复"与"再评"由调用方按 verdict 执行（同 saga/circuit/tx_contract 的编排中间层定位）。
- 段解析为确定性规则（行级 `## ` 标题 + `- ` 列表），不强求 LLM 语义理解——四段式**格式契约**由调用方（提示词模板）保证，工具只做收敛与完整性校验。
- 与 Ω verify 的验收（spec schema+fingerprint）互补：Ω 验"成果 vs 语料"，eval_feedback 验"反馈 vs 四段式"。

## 五、结论
Anthropic E/O（Building Effective Agents + 2026 Harness"agents 自评偏向自夸"实证）+ Self-Refine（2303.17651）+ Reflexion（2303.11366）+ zubi.ai 四段式——四锚点支撑"反馈收敛 eval_feedback"：把 AI 项目管理的"反馈"从叙事升级为**可计算契约**（Defects/Evidence/Fix/Acceptance + 确定性 verdict），E/O 闭环落地；纯 MoonBit 可复现（确定性解析 + 计数，零 LLM 自评，零新范式）。
