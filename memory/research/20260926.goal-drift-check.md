# 调研档：全局目标校验 goal_drift_check（R100 候选 · 2026-09-26）

> 来源（WebSearch 实检）：Goal Drift 技术报告（arXiv 2505.02709，2026-05——goal drift/cascade drift：更强模型被弱 agent 轨迹前置条件化后继承漂移）；Zylos 长程规划综述（goal re-anchoring：周期性地把原始高层目标重新注入上下文）；AI Planning Framework for LLM Web Agents（arXiv 2603.12710——**context drift**（Dongre et al. 2025）：agent 执行中逐渐丢失原始目标；并提 **Repetitiveness Rate** 可计算指标度量重复子问题）；IntentCUA（arXiv 2602.17049, AAMAS 2026——"drift from user intent + repeatedly solve routine subproblems → error accumulation"）；HiMAP-Travel（ICML 2026——**transactional monitor 跨并行 agent 强制 budget+uniqueness 约束**，防重复/防漂移）。
> 前置：R98 plan_revise（反馈修订）、evolve 包 jaccard/词法（R13 critic 已有 tokens/jaccard 单真源）。本档为 BACKLOG P2 首项「全局目标校验：每子任务完成后校验是否偏离根目标（non-redundancy）」。

## 一、核心矛盾（为什么需要目标校验）
- 长程执行的两个失败模式（Zylos/2505.02709）：**context 机械退化**（工具调用过多后遗忘早期结果）与 **语义 goal drift**（agent 渐失原始目标，被最近指令替代——Dongre context drift）。两者都需要不同缓解。
- 现状：fist-mbt 子任务完成后 `verify` 只验"交付物符合语料"（Omega）或"五段式"（docs_gate），**不校验子任务是否仍服务于根目标、是否与兄弟重复**——"拆"了但没人看"往哪拆"。Multi² 明确 hierarchical 缓解 objective drift；HiMAP 用 transactional monitor 强制 uniqueness（防重复子目标）。
- 项目原则"评测是计算"：不引入 LLM 自评——把 drift/redundancy 变成**可计算相似度判定**。

## 二、拿来主义落地（fist-mbt 版蒸馏）
| 外部信号 | fist-mbt 落地设计 |
|---|---|
| goal drift / context drift（2505.02709 / Dongre 2025） | 新原语 `goal_drift_check`：子任务描述/交付物 vs 根目标描述的词法相似度过低 → drift_suspect |
| Repetitiveness Rate（2603.12710 可计算指标） | 子任务 vs 其兄弟子任务相似度过高 → redundant_suspect（重复造轮子，non-redundancy） |
| 目标重锚定（Zylos goal re-anchoring） | 返回 `re_anchor` 提示（把根目标重新注入），与 R63 父计划回注协同 |
| HiMAP uniqueness transactional monitor（ICML 2026） | 相似度判定纯计算、幂等、只读——多 agent 提交前可批量门禁 |

## 三、设计要点（复用避免造轮子）
- **复用**：词法/jaccard 直接用 `@evolve` 的 `tokens`/`jaccard`（R13 evolve_critic 单真源，不新造）；兄弟收集用 `children_of`（R88/R98 同款）；子树用 `subtree_ids`。
- **数据流**：`goal_drift_check(root_task_id, subtask_id?)` →
  1. 读根任务描述（goal）；subtask_id 缺省时校验全部后代；
  2. 每子任务：drift = 1 - jaccard(goal tokens, subtask tokens)；redundancy = max jaccard(subtask, 每个兄弟)；
  3. 阈值（drift > 0.7 → drift_suspect；redundancy ≥ 0.7 → redundant_suspect；其余 aligned——对齐 critic 的 0.70 阈值口径）；
  4. 返回 { root_task_id, checks:[{subtask_id, drift_score, redundancy_score, verdict, re_anchor}], counts, note }——纯计算只读不写库。
- **零回归**：新工具独立注册（96→97），不改 verify/omega 既有语义；可选后续接入 verify 门禁（默认关闭）。

## 四、验证草案
- 单测：子任务描述与根目标高度重叠 → aligned / 低重叠 → drift_suspect（re_anchor 提示）/ 两兄弟高度重叠 → redundant_suspect / 空子树 insufficient / 阈值边界。
- E2E：award_demo 加 R100 段（拆解后校验 drift/redundancy 分布）；守卫族 + cleanup CLEAN。
