# 调研档：局部补偿控级联（R96 候选 · 2026-09-26）

> 来源（WebSearch 实检）：Babli, Sapena & Onaindia 2023《Plan Commitment: Replanning versus Plan Repair》（Engineering Applications of Artificial Intelligence 123, DOI 10.1016/j.engappai.2023.106275）；arXiv 2609.19654《Replan, Repair, or Edit?》（2026，旅行 agent 修订经验评估）；arXiv 2607.24167 FCPAgent《Falsifiable Commitment Planning for Self-Correcting Web Agents》（2026）；ICG-Restore（Preprints 202604.1634 / AI 2026, 7(8):294，minimal-edit repair）。
> 前置：R92 已落地 Saga（Garcia-Molina & Salem 1987），saga_rollback 为**全局 LIFO** 收尾；本档为其"同源 P2"设计最小修复切片（history-aware local compensation）。

## 一、核心矛盾（为什么需要局部补偿）
- R92 saga_rollback 语义 = 对链上**全部** pending 步骤严格倒序补偿（整树收尾）。当链某一步失败但**只有下游依赖切片受影响**时，全局收尾会过度补偿——把本可保留的已接受承诺（accepted commitments）一并撤销，之后被迫整树重规划。
- 规划文献把「修复失败计划 vs 从零重规划」作为基本二分：**replanning** 从新情境重新生成计划（弃原计划）；**plan repair** 修复既有计划、尽量保留其部分与结构、只做最小扰动。经验证据（2609.19654）：层次/局部修复比全重规划**改动更少、保留更多已接受承诺**，且推理开销更低。
- Babli 2023 提出 **plan commitment** 性质：agent 修复自己失败计划时，应尽量减少对**同一环境里其他 agent 计划**的负面影响（"responsible repair policy"）——多 agent 社区语义与 fist-mbt 的多任务 DAG 社区同构。
- FCPAgent 2026 的 **scope-aware repair**：诊断出 falsifier 后，确定**必须修订的最小组件**（smallest component），而非整计划重来。

## 二、拿来主义落地（fist-mbt 版蒸馏）
| 外部信号 | fist-mbt 落地设计 |
|---|---|
| plan repair > replanning（保留承诺） | 新原语 `saga_repair`：给定失败步骤，计算**最小补偿切片**（failed + 其依赖闭包中的 pending 下游），只补偿切片、保留切片外承诺 |
| plan commitment（控对他人影响） | 切片计算**历史感知**：复用 saga_log 注册序 + 任务表 depends_on（R39/R42 已建 DAG 边），失败步骤的下游依赖闭包 = 真正受影响者；未受影响步骤 KEEP |
| scope-aware（最小组件） | 输出 { compensate:[按 LIFO], keep:[], basis:"depends_on|order", note }，与 saga_rollback 同「返回序列、执行者执行」抽象；可选 mark 消费语义 |
| 级联控制 | 与 dag_mc 关键度/近关键路径协同：只补偿"最长路径受影响"切片，杜绝**涟漪撤销** |

## 三、设计要点（对照 R92 现状）
- **复用**：saga_log 表（无需新表——切片判定用既有 `list_saga_actions` + 任务 `depends_on`/parent 链）；幂等 mark 语义同 saga_rollback；`clear()` 已覆盖 saga_log。
- **数据流**：`saga_repair(ns, root_task_id, failed_step, mark?)` → 读链上 pending 步骤（注册序）→ failed_step 的 task_id 经 depends_on 传递闭包求受影响 task 集 → 切片 = failed + 闭包 ∩ pending → 切片内按 id 倒序（LIFO）→ keep = 链上 pending ∖ 切片。
- **缺省语义**：任务表无 depends_on 时退化为「failed + 其后注册的 pending」（order 感知，history-aware 兜底），不依赖 DAG 完备。
- **零回归**：新工具独立注册（94→95），不改 saga_register/saga_rollback 既有行为；saga_rollback（全局）与 saga_repair（局部）并存，语义互补。

## 四、验证草案
- 单测：有 depends_on 时切片只含失败任务下游（旁路兄弟 keep）/ 无 depends_on 退化 order 切片 / mark 幂等消费 / 空链 insufficient / clear 清空回归。
- E2E：注册 3 步链（1→2→3 依赖），1 失败 → repair 只列 1(+2?)…（按闭包与注册序断言 compensate/keep 精确集合）。
- 全量回归 + 守卫族 + cleanup CLEAN。

## 五、与机制设计家族叙事
拆解→排程(PERT/CPM + dag_mc)→预算→派单→看护(Phi)→补偿(Saga 全局 LIFO)→**局部补偿(saga_repair 最小切片控级联)**——"失败优雅收尾"从"整树收尾"进化到"最小扰动、保留承诺"，直接兑现用户建议「计划性增强」与 BACKLOG P2。
