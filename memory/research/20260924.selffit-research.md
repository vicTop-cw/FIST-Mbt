## 一、自我记忆（Hermes 为锚）该怎么建

Hermes 的三层记忆设计，对位 fist-mbt 现状给 3 条可移植动作：

| Hermes 机制 | 一句话 | 对 fist-mbt 的动作 |
|---|---|---|
| **分层记忆**（USER/MEMORY 热层 + SQLite/FTS 冷归档 + skills） | 热层常驻 prompt、冷层按需检索 | memory/ 四件套=热层；`memory/log`+`reviews/`=冷归档；DGM 档案库=技能层 |
| **字符硬上限 + 头部用量显示，满则合并删减** | 防无限膨胀 | 给 product/target/thinking 设上限；reviews/ 无限增长 → 收敛合并 |
| **三种写时刻**：上下文压缩 / 子任务完成(checkpoint) / 周期 nudge | 记忆在关键时刻落盘 | 新增 checkpoint：`verify` 通过 → 报告收敛写 target/product + reviews 缩编 |
| **默认冻结快照 + 按需 FTS 精确检索**（不全文注入） | 保前缀缓存、省 token | 检索改为「冻结快照 + 按需 grep/关键词精确」，不每轮全文注入 |

**应抄的 2 个前沿机制**：
- **Mem0「只增不改 + 软遗忘」**：新事实只追加不改旧；陈旧条目按 recency（0.3–1.5×）软降权而非删除 —— 保历史不丢、记忆网有生命周期。
- **A-Mem「关联链接」**：写入/更新时建带描述/关键词的 note，并回写老条目标记关联 —— 让记忆网自演化（`task_plan_deep` 前可注入相关关联）。

**最小 MCP 工具增量**（挂在既有 verify/生命周期，不破坏无状态语义）：
- `memory_consolidate`：verify 通过后把报告收敛写入 product/target + reviews 缩编（checkpoint 写时刻）
- `memory_gc`：上限触发合并/软降权归档（不硬删）
- `memory_link`：建 A-Mem 式关联，供 plan/claim 前注入

## 二、自进化机制（可抄 3 个）

| 来源 | 机制 | 转到 fist-mbt |
|---|---|---|
| **Harness RSI**（arxiv 2609.14857） | 冻结底层模型，只演化**外层系统**（AgentLoop/Observation/Tool/Context/Completion 五模块各自独立演化）；**改进必须能泛化到产生它的经验之外才作数**，评测与训练严格隔离 | 自驱「审视」只改外围流程（回传格式/门禁阈值），且必须用独立评测集（不参与训练的样本）验证才写回 —— 天然符合你 Omega 门禁 |
| **EvolveR**（arxiv 2510.16079） | 把交互轨迹离线蒸馏成「可复用原则」，在线检索重组，动态去重+打分 | 验收通过的任务 → 蒸馏成原则回写 **DGM 档案库**（补强既有 evolve_sample）；打回项作负样本 |
| **SE-Agent**（arxiv 2508.02085） | 三条算子：修订/重组/精炼；解路径当「物种」池，交叉取优片段，精英保留 | 打回的错误路径入池 → 重组「哪段定位好+哪段修复好」→ 精英保留下轮复用 |

参照：Meta APG（静态分析+测试反馈）与你的 Omega 验证同源，可作门禁阈值参照。
