## 一、外部调研结论（可借力/可设计完善的范式）

### 1. Repo Map（项目地图）模式 — 采纳为本轮 centerpiece
- 来源：Agent Patterns Catalog `repo-map-context` / agentpatterns.ai `repository-map-pattern`。
- 要点：给 agent 一张**紧凑、按重要性排序的代码库符号/依赖地图**，让它先地图后读文件，避免全项目盲目 grep。
- 落地到 fist-mbt：现有 AGENTS.md 只有目录级结构 + 工具名清单，**无「src/ 各子包职责总览」「从哪看起」引导**，缺一个 agent 首读入口。→ 本轮新增 `fist://map` resource：返回项目结构地图（各包职责 + 68 工具分组 + 入口引导），JSON 机器可读。

### 2. 任务图/编排论文 — 佐证 fist-mbt 递归拆解定位
- **DALIA**（arXiv 2601.17435）：声明式 agentic 层，能力语义模型 + 确定性任务图，强制分离 discovery/planning/execution。→ 佐证 fist-mbt「发现(claim/conflicts)→规划(plan_deep/DAG)→执行」的分层是可演绎的。
- **TURA**（arXiv 2508.04604）：DAG-based Task Planner 构最优并行执行计划。→ fist-mbt 已有 DAG 六件套（dag_critical_path/parallelism/check/ready/sort/ascii），已验证方向正确。
- **AgentX**（arXiv 2509.07595）：Stage→Planner→Executor 三阶段。→ 与 fist-mbt「根→拆→叶」同构。
- 结论：fist-mbt 的递归拆解 + Omega 强验证 + DAG 是其差异化护城河，无需再造；本轮在其上做「地图/引言」增强即可。

### 3. MoonBit 进展（可借力/拿来自用）
- **v0.8 `declare` 关键字**：AI 原生规范——`declare type/fn/impl` 让 AI 读了规范即可实现。→ 可考虑在 omega 语料/`task_plan_deep` 中落「declare 式规格」作为子任务契约（本期不实现，记入调研）。
- **v0.9 `regex` 稳定**：`s =~ re"..."`。→ 可替换 docs_gate/check 中的硬编码 `contains` 类检查（可选）。
- **v0.8 `@fs.tmpdir(prefix~)`**：临时目录。→ 整洁主线的临时脚本落盘标准（记入调研）。
- **v0.9 list comprehension**：`[ for ... if ... => ... ]`。→ 简化污染清理/过滤逻辑（可选重构）。

1. **无项目地图入口**：AGENTS.md 缺「从哪看起」；lib.mbt 只 re-export 4 类型/1 函数，未展开子包职责。→ 本轮 `fist://map` + AGENTS.md 补「地图/入口」段。
2. **工具分组文档与实际注册脱负载风险**：68 工具分组在 AGENTS.md，但新增的 evolve_asset_register(68) 是否已在分组表？→ 本轮校对。

4. **测试子代理回传五段式**已在 omega/check 落地，可复用；docs_gate 已接入 → 本轮无需新造。
