- **环境教训（沉淀）**：
  1. **WSL NAT 模式不镜像 Windows localhost 代理**（启动横幅明示），直连 PyPI ~27kB/s，4.4MB wheel 两轮下载超时。等效替代：`pip install --no-index` 装 `/mnt/e` 上本地 wheel，先与 PyPI JSON API 的 sha256 digests 逐一核对 MATCH（三包全 MATCH）作为"同一 artifact"证据；真实公网源安装验证放在 Windows venv 做双保险。
  2. **WSL stdout 走管道会被 UTF-16/编码搅碎**（wsl.exe 输出带 NUL），可靠做法：WSL 内命令把输出落到 `/mnt/e/...` 共享盘文件，Windows 侧 `read_file` 回读；`tr -d '\0'` 只治标。
  3. **`vools.api` 没有 memoize**（真实路径 `vools.curried.composition.memoize`，顶层导出是拼写不同的 `vools.memorize`）——冒烟脚本首版按假设路径写导致一次 ImportError，修正后重跑；教训：验证脚本里的 import 路径也要以源码为准，不凭记忆。
  4. **"源码面 ≠ 发布面"风险两现**：`md/rich/`（被已改代码引用但未跟踪）、`actus/_proc.py`（合并后新出现的引用）——wheel 按 setuptools 文件系统打包，不提交也会进包；发布前用 zip namelist 抽验关键文件是否真在 wheel 里。
  5. **`_proj_vools` 是指向真仓的 junction**，且 realpath 仍被判出 FIST-Mbt 工作区根——vools 仓内的读改写只能走 bash（python 显式 UTF-8 patch + 回读断言 count==1），文件工具不可用。
