FIST-Mbt · 目标项目配置

生成 fist.mcp.json（连接 + 环境）与 fist-runtime.json（模式/开关/看门狗/六顶帽/路由预设）

① 连接偏好

写进目标项目 fist.mcp.json 的 mcpServers.<serverName>。

正则 ^[A-Za-z0-9_-]{1,32}$
默认 fist-mbt（安装器 shim，黑盒路径优先）。填本仓绝对路径会导致换机失效。
. = 目标项目根目录
1..600000，默认 30000
如 ["serve","--ns","default"]；留空数组表示启动默认模式
默认 false

② 重连策略 reconnect

断线重连参数，缺省即可。

③ 环境变量（只填「名称」，不填真值）

凭据不进配置。 这里填的是 env 里的环境变量名 → 占位/取值；真正的密钥只来自运行环境变量。 白名单与服务端 mcp_config_scaffold 的 mcp_env_whitelist 严格一致； 若你把 api_key/token/secret 之类直接写进值，服务端会整笔拒绝。

常用：FIST_PROJECT_DIR（目标项目根）、FIST_DB_PATH（台账库）、FIST_OFM_ENDPOINT/FIST_OFM_KEY（外部服务接线）、GitHub/GitCode 同步令牌等。

④ 运行时策略预设（不进 MCP 配置 → 生成 fist-runtime.json）

这些开关不是 fist.mcp.json 的字段，而是各工具的调用参数（服务端不读它们的环境变量）。 本页把选中的开关聚成一份 fist-runtime.json，并在「应用清单」里逐条给出落到哪个工具的哪个参数， agent 拿到后据此构造真实的工具调用。

polish/tidy 模式禁发布新功能；fix_and_merge 需 GitHub token

定时任务调度间隔（外部 schedule 用）

⑤ 生成

点「生成并预览」产出 A) form_json（交 mcp_config_scaffold 校验）+ B) fist-runtime.json（运行时预设）+ C) 应用清单（开关→工具参数）。落盘由 agent/安装器做。

A) fist.mcp.json（连接 + 环境，可落盘）
B) fist-runtime.json（运行时策略预设）
C) 应用清单 —— 每个开关落到哪个工具的哪个参数
点「生成并预览」后显示。

校验流程：把 form_json 传给 mcp_config_scaffold（服务端校验 + 凭据硬门）， 它返回可落盘的 fist.mcp.json 正文与 unknown_keys； 落盘为目标项目根目录的 fist.mcp.json。fist-runtime.json 按「应用清单」 落到对应的 task_plan_deep / watchdog_tick / task_challenge / debate_convene / model_route 调用参数上。
