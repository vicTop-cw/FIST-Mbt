# autoplan 协议 v1 —— 计划投递、自主执行与裁决清单

> 对标：autoplan（个人开发者作品）——丢计划进去，agent 默默实现；拿不定主意的
> 出裁决清单附建议；使用者（agent/human）添加反馈调整优化。
> 本协议给出 fist-mbt 的等价实现：**全部复用既有机构，零核心改动**（P0 红线）。

## 1. 能力映射（autoplan 需求 → fist-mbt 现成机构）

| autoplan 能力 | fist-mbt 等价物 | 状态 |
|---|---|---|
| 丢计划进去 | `autoplan drop`（计划文件 → 拆解 → publish 入池） | 本协议 v1 新增（薄层） |
| agent 默默实现 | 服务常驻 + executor/巡检认领执行（claim→execute→submit） | 已有 |
| 拿不定主意 → 裁决清单 | **裁决任务**：标题带 `[裁决]` 前缀的入池任务，描述含 问题/选项/建议 | 本协议 v1 新增（约定） |
| 使用者添加反馈调整 | verify（验收/打回）+ task_events（append-only 账） | 已有 |
| 自主进化 | 管家巡检（每小时）+ mcp-watcher 触发 | 已有 |

## 2. 计划文件格式（markdown）

```markdown
# <计划标题>

- [ ] <工作项 1>
- [ ] <工作项 2>
? <裁决问题> | 选项：<A> / <B> | 建议：<A>
```

- `- [ ]` 行 = 工作项 → 逐条 publish 成任务（ns=autoplan，created_by=human_steward）
- `?` 行 = 裁决项 → 标题前缀 `[裁决]` 的工作项，描述末尾附裁决头
  （`裁决问题|选项|建议`），完成后由 verify 反馈记录所选选项
- 其余行（标题/段落）忽略，可自由写背景

## 3. 生命周期

1. **drop**：`python scripts/autoplan.py drop <计划.md> [--service http://127.0.0.1:18640]`
   —— 计划拆解入池（工作项 + 裁决项），返回任务 id 清单
2. **自主执行**：任一在线 agent 服务认领执行（claim→execute→submit），与普通任务无异
3. **裁决清单**：`python scripts/autoplan.py decisions [--service ...]`
   —— 列出 ns=autoplan 下所有 `[裁决]` 任务（问题/选项/建议/当前状态）
4. **裁决反馈**：human（或被授权 agent）对裁决任务 verify/打回，所选选项写进
   verify 反馈与 task_events —— 任务闭环即裁决落定

## 4. 纪律

- 裁决任务只是**约定形态**（标题前缀 + 描述结构），不改状态机、不加工具——
  升级为一等公民（专用工具/看板）的前提是 v1 跑通且消费面出现
- drop 幂等：同标题工作项不重复入池（按描述前缀核对）
- 裁决项**不阻塞**工作项：agent 遇到依赖裁决的工作项照常推进可推进部分，
  未决部分留任务账（拿不定主意≠停工）
