# 探针写作规范（probe-authoring）

> **来源**：2026-10-24 task-17（A 路 bugfind）实战副产品。
> 该单我第一版探针**自己造了一份假绿**——`assert_true(true)` + `println(...)`，
> 得 `206/206 全绿`而读数**一行没出**。这份规范是那次踩坑的固化，
> 不是设计推演。所有数字都是**实测**，不是估计。
>
> **判例-19**：`assert_true(true)` 是能写出来的最危险的断言。**探针必须能"红"才能证明它真在看。**

---

## 0. 一句话

**探针的产出是"读数"，不是"通过"。一个只会绿的探针，等于没跑。**

---

## 1. 两条铁律

### 铁律 1：不许 `println` 带读数

`moon test` 的 runner **不透传被测进程的 stdout**。
`println("读数：…")` 在测试里**什么都不显示**，而 `assert_true(true)` 让测试**绿**。

两者叠加 = **光谱上最坏的一种假绿**：测试通过了，读数丢了，你还以为看过了。

**实测**（task-17 第一版探针）：

```moonbit
println("PROBE_RESULT: kids=… lost_omega=…")
assert_true(true)
```
```
Total tests: 206, passed: 206, failed: 0
$ grep PROBE_RESULT      ← 零命中
```

### 铁律 2：不许 `assert_true(true)` 收尾

它不验证任何东西，只把"我跑到了这里"伪装成"我验过了"。
探针里**必须**有一个会失败的断言，且失败信息里带着读数。

> 自测法：**把被测代码改坏，探针必须红。** 如果改坏了还绿，探针是装饰。

---

## 2. 正确手法：读数编码进**测试名**

`fail()` 的正文会被 runner **截断**（实测见 §3），但**测试名完整可见**（102/102）。

**两种载体，实测差别很大**：

| 载体 | 能否装读数 | 说明 |
|---|---|---|
| `println` | ❌ **完全不可见** | runner 不透传 stdout |
| `fail()` 正文 | ⚠️ **只余 ≤26 字符**，且常被路径吃掉 | 长读数**必丢** |
| **测试名字符串** | ✅ **102 字符完整可见** | 但**源码里写死，运行时不能改** |

⚠️ **关键矛盾**：测试名容量最大，但探针的读数**是运行时算出来的**，
而 `test "…"` 的名字**在编译期就固定了**，不能拼接变量。

⇒ **实操结论**：把读数压成**极短的编码串**（≤20 字符）放进 `fail()` 正文最前面。
这是实测唯一稳定的路（见写法 B）。

### 写法 A（❌ 我第一版，失败）——长读数塞 `fail` 正文

```moonbit
println("PROBE_RESULT: kids=… lost_omega=…")   // ← 不可见
fail("PROBE_RESULT kids=\... lost_omega=\...")  // ← 被截断成 "PROBE_RES"
assert_true(true)
```

实测拿到：`FAILED: PROBE_RES` —— **8 字符，读数全丢**。

### 写法 B（✅ **实测可用**，本规范推荐）——短编码串 + `fail` 触发

```moonbit
test "PROBE_F3" {
  let kids = …
  let lost = …
  let p = if omega_enabled(root) { "1" } else { "0" }
  let tag = "k" + kids.length().to_string() + "L" + lost.to_string() + "P" + p
  fail("PH" + tag)      // 总长 ~10 字符 << 26 上限
}
```

实测输出：
```
F| … test … ("PROBE_F3") failed: … FAILED: PHk2L2P1
```
`grep -oE "PHk[0-9]+L[0-9]+P[01]"` → **`PHk2L2P1`** ✅ 完整命中。

**编码设计要点**：
- 前缀固定（`PH`）+ 字段字母分隔（`k`/`L`/`P`）+ 数字值 ⇒ 可正则稳定提取
- 每字段一位或两位数字（`k2` `L2` `P1`），总长压在 ~10 字符
- **绝不放自然语言**（中文/空格会被 runner 输出格式干扰）

## 3. 实测标定（这些数字是量出来的，不是估的）

标定探针（临时，已删）：

```moonbit
test "CALIB_BODY_0123456789_…(102 字符)…_END" {
  fail("BODYSTART_0123456789_…(102 字符)…_BODYEND")
}
```

**实测结果**：

| 位置 | 写入长度 | 可见长度 | 是否完整 |
|---|---|---|---|
| **测试名** | 102 字符 | **102 字符** | ✅ **完整可见**（末尾 `_END` 在） |
| **fail 正文** | 102 字符 | **26 字符** | ❌ 截断（只剩路径 `src/engine/zz_calib_wbtest`） |

**结论**：
- **测试名承载能力远大于 fail 正文**（102 vs 26）
- fail 正文的 26 字符里还要含路径，**实际留给读数的空间接近 0**
- ⇒ **读数必须落在测试名侧，或用一个 ≤20 字符的短串贴在正文最前**

## 4. 探针三重自检（缺一不可）

写任何探针，跑之前先自问：

| # | 问题 | 不满足的后果 |
|---|---|---|
| **1** | 读数从哪**出来**？（不能是 stdout） | 假绿：绿了但没读数 |
| **2** | 把被测代码**改坏**，这探针会红吗？ | 装饰：永远绿 |
| **3** | 读数能不能**被 grep 稳定命中**？ | 要人肉看、无法自动化 |

第 2 条尤其重要。task-17 的 F3 探针在**验证阶段用 `assert_true(true)`** 是对的
（那次目的是"取读数"不是"断言契约"），但**它必须配合 `fail()` 把读数逼出来**才成立。

---

## 5. 反模式清单

| 反模式 | 为什么坏 | 正确做法 |
|---|---|---|
| `println("…")` 带读数 | runner 不透传 stdout | 编码进 fail/测试名 |
| `assert_true(true)` / `assert_true(1 == 1)` | 不验证，只伪装 | 让它**能红** |
| `assert_eq(x, x)` | 恒真 | 断言**独立来源**的两个值 |
| `fail("孩子很长的一段读数…")` | 正文截断到 26 字符 | 短串 ≤20 字符，或进测试名 |
| 探针留在 `src/` 里忘了删 | 污染包、影响全量测试数 | **跑完即删**，并在报告里注明"已删" |
| 探针用 `zz_` 前缀但不说明 | 后人以为是正式测试 | 文件头写明「临时探针，读完即删」 |

## 6. 探针的生命周期纪律

```
1. 写进 src/<pkg>/zz_probe_<id>_wbtest.mbt（zz_ 前缀让排序靠后、一眼可辨临时性）
2. 文件头必须写：「临时探针，读完即删」+ 测什么
3. 跑：python scripts/moon_test_env.py --target js <pkg>
4. 抓读数：grep -oE "<你的 tag 正则>"
5. **立刻 rm**，并 git status --short -- src/ 确认干净
6. 报告里写清：探针已删 + 探针期间测试读数（如 206/206 → 205/206 故意红 → 删除后恢复）
```

> **task-17 实证**：探针期间 `Total tests 206, passed 205, failed 1`（故意红），
> 删除后恢复全绿。**这个"故意红"本身就是探针有效的证据。**

## 7. 什么时候该用探针（以及什么时候不该）

**该用**：
- 要确认某条代码路径**真实取值**（而不是"我读代码认为"）
- 要构造现有测试**零覆盖**的场景（task-17 的 F3 就是这样发现的）
- 规则扫描（issue_scan）看不见的**语义缺陷**

**不该用**：
- 该写正式测试的（探针是一次性的，正式测试要有断言 + 保留）
- 能靠纯 Python/sqlite 复刻的（继续用 `temp/*.py`，更快且不污染 MoonBit 包）
  - task-17 的 F1 就是这么做的：`temp/probe_f1.py` 复刻判据，5 格全跑

> **经验**：**能不进 MoonBit 包就别进**。F1 用 Python 复刻判据零成本；
> F3 必须真引擎（涉及 `plan_deep`/`create_task`/`omega_enabled` 全链路），才值得开 wbtest 探针。
