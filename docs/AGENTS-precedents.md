### 判例-32：探针必须先在新样本上标定（2026-10-27 立 · BUG-428）

**被测对象的标识符可能被工具链变形。** 实测 MoonBit 的 JS 产物把标识符里的 `_` **逐字翻倍**：

```
grep -c  'omega_orphan_of_archived_parent'        cli.js → 0    ← 裸串（假红）
grep -cE 'omega_+orphan_+of_+archived_+parent\('  cli.js → 3    ← 容忍变形（真读数）
实际: function _M0FP411vicTop_…6engine35omega__orphan__of__archived__parent(t)
```

⇒ **裸字符串探针在「未变异的、新鲜的」产物上就会报「找不到」** —— 看着像「产物旧」，
实际是「探针不会认」。实测代价：BUG-417 的诊断因此误判 40 分钟（四个逻辑条件全查过、全部正常，
真因是「进程跑的是旧构建」而「判断旧构建的方法本身失灵」）。

**硬要求**（任何「grep 产物找符号」的判据，上线前必须做）：

1. **在新鲜样本上标定一次**：拿刚构建的产物跑一遍，确认探针**能认出来**（否则它的「找不到」没有意义）；
2. **容忍变形**：`_` → `_+`（或等价宽松式），且要求命中后紧跟 `(` —— 否则 bundle 里大量工具名**字符串**会误命中；
3. **反脱锚格**：符号被改名/删除时判 **`rc=4「尺子坏了」`**，**不是**判「被测对象旧」
   —— 判据自己的腐烂与对象的陈旧是两种结论，混为一谈会让下一个人去修错的东西。

**同族口径**：**版本号 PASS ≠ 代码新鲜。** 只比版本字符串的守卫
（`check_dist_snapshot` 的前身）在「快照版本 0.3.10 == moon.mod 0.3.10、代码是 3 天前的」时照样绿。
要比内容，不能只比号。落地见 `scripts/check_deployment_freshness.py`（48 格自检，7 处变异对照）
+ `scripts/_deployment_symbols.py`（探针单一真源）。

### 判例-33：自检要测「配置这根线」，不是「服务本体」（2026-10-27 立 · BUG-437）

**判据绿了整场，而生产入口一次都没起来。** `scripts/mcp_smoke.py` 一直 PASS（171 工具），
DSH 侧 `fist-mbt` 却恒报 `mcp-client(fist-mbt): server is disconnected` —— 因为 smoke 自己拼了
`[NODE, main_js, "serve"]` 直接拉 bundle，**绕过了 `.mcp.json` 那根真正出故障的线**
（`"command": "fist-mbt"` 在 Windows 无 shell 不可 spawn：裸名 → `ENOENT`，`.cmd` → `EINVAL`）。

⇒ 与判例-29「机制格 ≠ 实现路径格」、判例-32「版本号 PASS ≠ 代码新鲜」同族：
**「被测对象能工作」与「被测对象被正确接入」是两件事**，而用户只感知后者。

**硬要求**：任何「服务可用性」自检，必须用**生产配置的同一份启动描述**（`command` + `args` 原样）去 spawn，
不得自己拼一条更"好走"的路；绕路那一条只能在拿不到配置时当 fallback，且必须**明说降级**。

**第二条（同族不同面）：构建产物不是稳定属性。** 依赖「产物后处理」的东西
（ESM `require` 兼容层、`MOONC_OVERRIDE` 注入、`patch_esm_main.py` 这类补丁）**必须在每次启动时幂等重建**，
不能假设「上一次 build 之后它还在」。实测同一路径 `cli.js` 的 shim 在 **08:50 / 08:57 / 09:03 三次反复**
（并发构建各写各的）⇒ 不幂等的补丁等于没有补丁，且失效形态是「能启动、一用就死」（首次打库才崩），
比启动即崩更难判。**判据要盯「启动后真的用一次」，不能只盯 banner。**

**第三条（Windows 面）**：`spawn('x')` **不认 `.cmd`/`.bat`**（「node 18.20.2」起无 `shell:true` 直接 `EINVAL` —— 这是**行为变更版本**，不是地板声明），
也不认无扩展名的 sh 脚本。配置里写裸命令名**只在 POSIX 成立**。Windows 上要么写绝对 `node <js>`，
要么钉真 `node.exe`（PATH 首条常是 `dsh-desktop\harness\.desktop-bin\node.cmd` 垫片，
经 `cmd.exe` 转发会吞引号 —— BUG-380 同源）。

**落地**：`%LOCALAPPDATA%\FIST-Mbt\serve-launcher.cjs`（幂等补 ESM shim + 修双补丁 + debug/release 自动选 +
日志打**内容身份** mtime/size/sha8；**双路由**：`serve|version|demo|doctor|help` → MoonBit bundle，
其余 → `scripts/fist.py` 网关，网关子进程注入 `FIST_NODE=process.execPath` 避开 `node.cmd` 垫片）
+ `.mcp.json` 走 `node` + 该启动器 + 两份注册垫片（`~/.local/bin/fist-mbt.cmd` 与 POSIX `fist-mbt`，均委派它，
`.cmd` 另钉真 `node.exe`）；账本 BUG-437。

### 判例-34：**错误信息的指向 ≠ 错误的真实位置**（2026-10-28 立 · MoonBit 字符串拼接两次踩坑）

**同一天两次，都在 `src/server/server.mbt` 的 schema 描述上，都指向完全无关的位置。**

**坑 1（相邻字符串隐式拼接不存在）**：写
```moonbit
"第一行"
"第二行"
"第三行",
```
⇒ **2708 个级联错误**，第一条是 `The toplevel identifier boundary_probe is declared twice`
—— **所有顶层标识符都「declared twice」，且指向完全无关的文件**。

**坑 2（`+` 必须放行末）**：以为用 `+` 就对了，写成
```moonbit
"第一行"      ← 末尾没有 +
+ "第二行"
+ "第三行",
```
⇒ `Unexpected line`，**又指向 `schema(` 整块**。

**正确写法**：`+` 在**行末** —— `"第一行" +` / `"第二行" +` / `"第三行",`。

**⇒ 硬要求（判据）**：
1. **一个错误说「X declared twice」而 `grep` 只找到 X 一次** ⇒ **那不是 X 的问题**，
   是**解析器在别处失了同步** ⇒ **往前找**（离出错位置最近的、**我改过**的地方）。
2. **错误指向一个结构体/块的开头**（`schema(`）而里面某行"看起来对" ⇒
   **看那一行的行末**（少了 `+` / 少了 `,` / 多了 `"`）。
3. **改 9800 行的大文件前，先把片段写到 `temp/` 验语法**，贴完**立刻** `moon check`。

**同族口径（与判例-29/32/33 一脉）**：**工具给你的定位是「症状的位置」，不是「病因的位置」。**
判例-29 是「机制格 ≠ 实现路径格」、判例-32 是「版本号 PASS ≠ 代码新鲜」、
判例-33 是「服务本体 ≠ 服务接入」—— 本条是「**报错指向 ≠ 病因所在**」。

**代价实测**：Round 19 我把它误判成「并发编译把 `_build` 弄乱」，
理由是「`sleep 90` 后再跑就绿了」—— **真相是并发 lane 在 14:10:07 修好了我的语法**
（`95ea5106`）。**⇒ 「等一等就绿了」有三种可能**：别人 WIP 收口 / **别人修好了我的代码** /
缓存重建 —— **不能当成「我的判断被验证了」**，必须读 `git log` 看这几分钟里**有没有别人提交**。

**完整版见 `temp/moonbit_string_concat_pitfalls.md`**（两个坑 + 共同教训 + 流程建议）。

### 判例-35：**`--` 在 `git` 与 `grep` 家族里语义相反，且都不报错**（2026-10-30 立 · BUG-486/487）

**本会话实测 2 次「探针坏了、但表现为「搜到 0 个」」** —— 两次都不报错，只给出错误结论。

**坑 1（参数语义）**：
```bash
$ git grep -l "automator"            → 34 个文件   ✅
$ git grep -l -- "*automator*"       →  0 个文件   ❌ ← 我用的这条
$ git grep -l -- "automator.py"      → 27 个文件   ✅
```
`--` 之后在 `git` 家族里是 **pathspec**（路径过滤），不是 pattern ⇒ `*automator*` 被当成「路径通配」
⇒ 没有文件路径匹配 ⇒ **0 命中，且不报错**（与「确实没人引用」**输出完全一样**）。

| 工具 | `--` 之后是什么 |
|---|---|
| `git commit -F msg -- <paths>` | **pathspec** |
| `git grep -l -- <X>` | **pathspec**（X 被当路径过滤）|
| `grep -- <X> <file>` | **pattern**（`--` 用于防 pattern 以 `-` 开头）|

**⇒ 同一个 `--`，`git` 家族是「路径边界」，`grep` 家族是「选项边界」。名字近似、语义相反，且都静默。**

**坑 2（shell 转义）**：在 bash 里内联测正则时 `\$Version` 的 `$` 会被 shell 吃掉 ⇒
喂给正则的字符串已不含 `$Version` ⇒ 报「没命中」。**改用 `importlib` 加载真模块 + 不受 shell 干扰的字符串 ⇒ 立刻正确。**

**硬要求**：

1. **「一个探针对所有输入都给同一答案」⇒ 先怀疑探针。**
   实测我给 20 个脚本查引用，**20/20 全返回 0** —— 这个分布本身就是探针坏了的证据（真实世界不会这么整齐）。
2. **`git grep` 的正确写法**：pattern 在 `--` **之前** —— `git grep -l "pat" -- scripts/`。
3. **在 bash 内联测正则/字符串时，优先用 `importlib` 加载真模块**，别在 shell 里手抄一份被测对象。

**同族口径（与判例-29/32/33/34 一脉）**：判例-32 是「版本号 PASS ≠ 代码新鲜」、
判例-33 是「服务本体 ≠ 服务接入」、判例-34 是「报错指向 ≠ 病因所在」——
**本条是「探针的结果 ≠ 探针在工作」。**
**⇒ 静默不同比报错更难发现：报错会让人停下来，静默只会让人得出错误结论。**

### 判例-36：**标记 `FIXED` 必须写明「回归锁」**（2026-10-30 立 · R105 落地 · 决策单默认 A）

**「测试验收」≠「回归锁」。** 前者是「修完那一刻跑一遍绿了」，后者是「下一个人改回去时**当场红**」。

`templates/pipeline_mode_fix_and_merge.md` 只要求前者（`:20`「跑 `moon check` + `moon test` 确认修复生效且无回归」），
**⇒ 修完绿了、之后被静默改回去，没有任何东西会红。**
实测代价：`BUG-202`（high，把子串匹配改成词边界匹配）的修复**零测试**，
而它零调用者（`plan_route` 全仓无人调用）⇒ **改回去连运行时症状都没有**。

**硬要求（R105 起，`bug_fix` 已实现校验）**：`evidence` 必须**二选一** ——
1. **点名一条测试文件**（`_test.mbt` / `_wbtest.mbt`）或写「回归锁」；
2. **写明「本修复不需锁」的理由**（纯文案 / 纯配置 / 依赖侧修不了）。

**⚠️ 给出口 ② 是刻意的**：不是所有修复都该补锁。**无出口的硬规则会被绕过**
（`check_scripts_naming` 的 R4「豁免条目已失效」就是为此存在）。
**⚠️ 存量不追溯**：实测（R104）本仓能补锁的上限只有 **11 条**，其中 **5 条是身份/授权面**
（S1/S3 家族）——它们的锁该是**行为面判据**而非单测（判例-33：服务本体 ≠ 服务接入）。

**⇒ 新增「前置校验」时的连带**（R105 实测四类坑）：
① 各处负例用例都会**先撞新门** ⇒ 逐个排查；② 改 evidence **数据**要同批查**断言**（断言写死内容就会红）；
③ 用弃用写法（`not(...)`）会涨 warning ⇒ 回到基线；④ **必须同批改**参数描述**，
否则调用方按描述准备参数、在最后一步才失败。

### 判例-37：**覆盖是「行为」属性，不是「文本/比例」属性**（2026-10-30 立 · 本会话第 8 次同族误判）

**八次「找零覆盖/找缺口」全部误判，同一根源：**

| 轮 | 探针 | 以为是 | 实际 |
|---|---|---|---|
| R72 | 裸词 `moon check` | 9 个判据自跑 | **2 个** |
| R80 | 静态 `grep` 电池面 | 19 个缺面 | **0**（`auto_cases()` 动态生成）|
| R90 | 名似 `circuit_breaker` | Rx 重复实现 | **语义不同**（决策面 vs 管道算子）|
| R90 | 名似定时器 | 缺 Rx 复用 | **任务分级规则** |
| R97 | `supervisor_kill_apply_pause` 零引用 | 零覆盖 | **薄包装**（被包装者有 3 文件覆盖）|
| R100 | `phi_domain_error` 符号零出现 | 零覆盖 | **两条分支都有行为断言** |
| R103 | 账本「小记没提测试」 | 101 个无锁 | 三处探针缺陷 ⇒ **真缺口 0** |
| R110 | `evidence` ratio **0.27** 最弱 | 最弱包 | **零缺口**（数据层包的比例天然失真）|

**硬要求（找覆盖缺口的三步判据链）：**

1. **不要用比例/文本/符号名当证据** —— 它们只是**候选清单**。覆盖本质是行为：
   **唯一可靠证据是「改坏代码时某个断言会红」**（变异对照）。
2. **判「零覆盖」前必须两步**：① 它是不是某个**有测试的上层函数**的内部件/薄包装？
   若是 ⇒ **上层行为测试就是它的覆盖**。② 它的**分支**是否都被断言？
   **只有「既无上层、又无断言」才是真缺口。**
3. **比例只在「逻辑密集」的包上有信号。** `spec.mbt` / `store.mbt` 这类**数据层**包
   （结构定义 + 访取器）行数多、可断言行为少 ⇒ 分母大分子小，`evidence` 0.27 就是这么来的。

**⇒ 同族口径（与判例-32/35 一脉）**：判例-32 是「版本号 PASS ≠ 代码新鲜」、
判例-35 是「探针的结果 ≠ 探针在工作」—— **本条是「文本命中 ≠ 行为覆盖」。**
**⇒ 八次说明这不是「不小心」，是方法论缺口：我在文本层反复找行为证据。**

### 判例-38：**反引号出现的位置 ≠ 报关意图**（2026-10-30 立 · BUG-500 同轮 · R1 判据收紧）

判例-37 那张「八次误判表」被 `check_tools_sync.py` 的 R1 抓成 **5 个「文档声明了但 server 没注册」的工具**
—— `grep` / `circuit_breaker` / `phi_domain_error` / `supervisor_kill_apply_pause` / `evidence`
**全都不是工具**，是那张表在讲的**外部符号名**。

**真因**：R1 的旧口径是「表格行的**首个反引号 token** = 工具名」。这个假设只对**工具清单表**
成立（它写成 `| `dag_ready` | 说明 |`，工具名独占**首列整格**）；判例/规则类表格首列是
`R72` / `轮` / `阶段` 这类**纯文本**，反引号名落在后面的**叙述列**里。
⇒ **「哪一列有权声明工具」没被区分 ⇒ 「首个 token」成了任何反引号名的通行证。**

**硬要求（写规则表格时）**：

1. **规则/判例表格里不要裸写非工具符号名做首列**；要写就放进叙述列，并接受它**不再是工具声明**
   —— 判据收紧后（BUG-500），「首列不是单个反引号标识符」的行一律不参与工具名比对。
2. **反过来也成立**：真工具名要写在**首列整格**（`| `tool_name` | 说明 |`），
   否则收紧后的 R1 **看不见**它（这是本豁免**承认的代价**，见下）。
3. **改判据不许靠「整类表格免检」**：豁免必须定位到**列/形状**，不能定位到「哪一类表格」——
   后者会连带把工具清单表一起免掉，工具名漂移从此没人抓（`--selftest` 有对照格锁这一条）。

**⇒ 本豁免承认的代价**：真工具名若被写进叙述列（首列纯文本），R1 不再报关。
**宁可漏一个写在奇怪位置的真工具名，也不把规则表当报关单。**
**⇒ 同族口径**：判例-37 是「文本命中 ≠ 行为覆盖」—— **本条是「反引号的位置 ≠ 报关意图」。**

### 判例-39：改名不是接线，豁免按前缀匹配时改名会静默失去豁免（2026-10-31 立 · R115 实测）

`scripts/check_hardcoded_paths.py:74` 的豁免③「`scripts/_*.py` 是本机一次性脚本」按 `_` 前缀豁免 ⇒ `_run_check_t0r21.py` 被豁免、改名成 `check_t0r21.py` 后豁免消失 ⇒ 判据由绿转红。且该判据未在 ci.yml 接线 ⇒ 「电池外红着没人读」第四例。与判例-3「改名不是接线」同族但方向相反：判例-3 是「改了名没接上新名的引用」，本条是「改了名**失去**了按名/按前缀匹配的豁免」。**⇒ 改名前必须全仓扫一遍「按前缀/按名字匹配该文件名的判据豁免面」**（`grep -rn "scripts/_" scripts/check_*.py`），`EXEMPT_RULES`/`REGISTRY` 必须同批换标签（run_guards.py 已按此补 4 条精确文件名规则，理由逐字沿用被替掉的前缀规则）。

### 判例-40：机制格测不到自己的分发分支（2026-11-02 立 · R118 实测）

**写在 `--selftest` 内部的断言，永远测不到「`--selftest` 那个分发分支被摘掉」。**

给 `scripts/check_t0r21.py` 的 `--selftest` 立了「换分发目标 + 必炸桩」的机制格：把被分发到的函数换成一个必炸的桩，若分发真的发生，桩就会炸、格子就红。**变异对照（摘掉 `if "--selftest" in argv: return selftest()` 这一行）照样绿** —— 因为分支摘掉之后 `selftest()` 根本不会被调起（`--selftest` 落进取数侧、跑的是对真仓库的真检查），任何写在 `selftest` 内部的断言都测不到「分支没了」。

⇒ **判例-30 的第四形态**：不止「模式串自指」那种假绿，这一种是**看着在测，测的是一条变异够不着的路** —— 变异把路拆了，断言跟着路一起消失，锁自然不响。

**处置：删掉该机制格。**「自检开关被静默忽略」这道防线不在 selftest 内自证，而由**外部**判据 `check_arg_face_strict` 承担（真跑、喂 `--definitely-not-real`，按结果判）。

**⇒ 规则：selftest 内部永远测不到「自己的分发分支被摘」；分发面的防线必须由外部判据承担。**

### 判例-41：`git commit -- <path>` 不吃未跟踪文件（2026-11-02 立 · R119 实测）

`git commit -F msg -- docs/AGENTS-precedents.md`（该文件当时 `??` 未跟踪）报：

```
error: pathspec 'docs/AGENTS-precedents.md' did not match any file(s) known to git
```

**整笔提交原子失败**（什么都没提交）。`--` 之后是 **pathspec，只选已跟踪路径**；未跟踪文件必须先显式 `git add <path>` 再 scoped commit。

**⇒ `scripts/commit_scoped.sh` 的步骤 2（逐个 add）正是为此存在 —— 不要绕过它裸跑 commit。** 判例-11 教的是「commit 必须带 `--`」，但 `--` 只保证**不带上别人的东西**，它不负责**把我自己的新文件放进去**；两件事各管一半。

**连带实测（比上面那条更危险）**：提交失败时 `&&` 链上的 `git push` 仍可能执行，把**别的 lane 留在本地 `main` 的提交**一并送到远端（`125fa094e` 巡检轮 26 即此例）。**⇒ push 前必须确认 `git log origin/main..HEAD` 里没有不属于自己的提交**；提交失败就停，别让 `&&` 链自己走下去（`set -e` / 显式判 rc 都比 `&&` 稳）。

同族口径：判例-11「两半法」、判例-35「`--` 在 `git` 与 `grep` 家族里语义相反且都静默」—— **本条是「`--` 的正面功能边界」：它挡得住多带，挡不住少带。**

### 判例-42：函数内赋值漏 `global` ⇒ rc=1 但不是「格子红」（2026-11-02 立 · R118 实测）

## 判例-46 · 注释自述的 fail-open 意图只落在一臂 = 另一半静默反向（2026-11-09 立 · 轮 182 车道 E 普查 / BUG-584 实锤）

而这条意图在 BUG-206 那一轮**只实现了 cool 臂**（`if cool_secs <= 0 { return false }`），now 臂原样留着

`issue_scan` 的「未用变量/过宽 catch」族不看**守卫不对称**；`engine_circuit`/`model_router` 的既有测试

比"没写测试"更危险的是"测试为注释的那半背书，而代码做另一半"。

**定律（新增判据/新车道时照做）**：
1. 见注释自称「已 fail-open / 已拒绝 / 已兜底」的**多操作数守卫**，逐臂核每一臂是否真有该分支；
   只有注释没有臂的那一臂就是缺陷，别把注释当证据（判例-「改名不是接线」的认识论反面：**注释不是实现**）。
2. 哨兵值（-1/0/""）参与的比较运算，测试语料**必须包含哨兵臂**；只喂合法域等于没测那一支
   （同族律：默认态走不到的那一支可能从来没绿过）。
3. 派生域上界不许写死年份/秒常数：`iso_domain_upper_secs()` 按 `iso_to_secs ∘ secs_to_iso`
   往返谓词**二分反解**，边界放宽时自动跟着走，不留第二份要人肉同步的口径；
   谓词不再单调即自拒回 0（宁可让调用方拒绝一切，不许「上界算大 ⇒ 绕回又回来了」）。
