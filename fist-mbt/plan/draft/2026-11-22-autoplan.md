# autoplan 协议 v2 —— 计划四区生命周期（初稿/定案执行/归档/终止 + 裁决/反馈双面）

> 对标：autoplan（个人开发者作品）——丢计划进去，agent 默默实现；拿不定主意的
> 出裁决清单附建议；使用者（agent/human）添加反馈调整优化。
> 全部复用 fist-mbt 既有机构（九态任务池/ACL/审计账），零核心改动（P0 红线）。

## 1. 计划四区生命周期（v2 核心）

```
                    drop（只入初稿，不执行）
   ┌──────────┐                        ┌──────────┐
   │  初稿区   │ ──── finalize（定案）──▶ │  执行区   │  仅定案计划的任务在池内流转
   └──────────┘                        │ (定案)   │  claim→execute→submit→verify
   ┌──────────┐                        └────┬─────┘
   │  终止区   │ abort（夭折，记录原因）      │ 全部任务终态（sweep）
   └──────────┘                           ▼
                                    ┌──────────┐
   feedback（功能反馈区，独立账）      │  归档区   │
                                    └──────────┘
   裁决区：定案计划的 [裁决] 项集中视图（decisions），比 v1 更清晰（按计划分组）
```

- **初稿区**：drop 只建计划记录，任务**不入池**——改到满意再定案
- **执行区（定案）**：`finalize` 才把工作项/裁决项 publish 进池流转
- **归档区**：定案计划全部任务终态后 `sweep` 自动归位
- **终止区**：`abort` 记录夭折原因；池内已发布任务如实标注（不静默删除）

## 2. 计划文件格式（markdown，同 v1）

```markdown
# <计划标题>

- [ ] <工作项 1>
- [ ] <工作项 2>
? <裁决问题> | 选项：<A> / <B> | 建议：<A>
```

## 3. 命令面（scripts/autoplan.py）

| 命令 | 语义 |
|---|---|
| `drop <计划.md>` | 新建计划 → **初稿区**（不执行） |
| `plans` | 四区视图：初稿/执行(定案)/归档/终止 全量盘点 |
| `finalize <plan_id>` | 定案：任务入池开始执行 → 执行区 |
| `abort <plan_id> "<原因>"` | 计划夭折 → 终止区（记录原因） |
| `sweep` | 全任务终态的定案计划 → 归档区 |
| `decisions [plan_id]` | **裁决区**：定案计划的 [裁决] 项（问题/选项/建议/状态） |
| `resolve <task_id> "<选项>"` | 裁决落定（宽容状态链）+ 记 laya-inbox |
| `feedback "<意见>"` / `feedback --list` | **功能反馈区**：对 autoplan 本功能的优化意见（独立账） |

## 4. 账本

- `.fist-mbt/data/autoplan-plans.json`：计划记录（id/标题/区态/条目/任务 id/时间戳）
- `.fist-mbt/data/autoplan-feedback.jsonl`：功能反馈（append-only）
- 裁决落定仍记 `laya-inbox.jsonl`（与 laya 侧共享通道）

## 5. 纪律

- 四区只是**计划记录的状态机**（v2 约定层），任务池九态机构零改动
- 初稿计划的任务不入池 ⇒ 「改计划」永不产生执行噪音
- abort 不删池内任务：如实标注计划终止，任务由 agent_service_stop/revoke 既有路径处理
- 反馈区 append-only：意见只增不改，采纳与否在后续版本说明
