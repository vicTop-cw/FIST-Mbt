## 六、沉淀（lessons）

1. **「内部函数已做的活，别在外层再做一遍」**是 R9 「函数体内 `list_all()`
   多次」的跨函数推广：`dag_slack_analysis` 已经算了 `dag_topo_order`，
   但它**不把 order 传给调用方**，于是 `dag_cost_route` 不知道已经算过，
   又算一次。**让底座函数「返回它算了什么」而不是「只返回调用方要的」，
   是最通用的解法**——虽然会增加 Json 大小，但相比多一次全库读，
   值得。

2. **fallback 兜底**：`dag_cost_route` 的 order 解析带了
   `match slack.value("order") { Some(Array) => ... _ => 回退 dag_topo_order() }`。
   即使 Json 结构被未来版本改动，也不会静默拿空 order 导致
   `for id in []` 直接跳过。

3. **DAG 底座性能收敛收官**：`dag_topo_order` / `dag_slack_analysis` /
   `dag_schedule` / `dag_cost_route` 四函数的 `list_all()` 与 `dag_topo_order()`
   调用已全部收敛为一次。后续任何新性能优化应转向其他热点。
