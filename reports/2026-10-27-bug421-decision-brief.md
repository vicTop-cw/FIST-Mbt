## 🎯 30 秒决策表

| 方案 | 收益 | 代价 | 我的建议 |
|---|---|---|---|
| **① 关掉整名**（`leader`/`lead` 不再给 Leader） | 少 1 条越权路：任何自称 `leader` 的 agent 拿不到军官面 | **现网掉级 0 人**（唯一 Leader 是显式注册，不是名字推断）；但**军官自报通道彻底关闭** | ⬜ 可关，但不是现在 |
| **② 不修，只标注** | 零风险、零工时 | 保留 1 条越权路（**攻击者必须同时满足**：能调 `reserve_scope` + 自称 `leader`） | ✅ **建议先走这条** |
| **③ 整名保留 + 名字与 `agents.role` 矛盾即报错**（Q3-i） | 堵住「自称 leader 就能拿军官面」 | 需改 `engine_rsv.mbt` 2 处 + 加锁；**且它只在「有登记」时生效，未登记仍靠推断** | ⬜ 技术上最优，等 422(b) 一起做 |
| **④ 整名保留 + 首次使用需显式登记**（Q3-ii） | 一次性成本换长期正确 | **要新增 MCP 工具面**（`agents_register` 当前未暴露）+ 动签名 | ❌ 工作量最大 |
| **⑤ 整名关掉 + 开放 Leader 自助登记**（Q3-iii） | 关掉越权口且保留自助 | **两件事都要做**：关整名 + 新建工具面 | ❌ 同上，且优先级低 |

**一句话建议**：
> **现在不单独修 421。等 422 的 (b) 落地后一起做方案 ③。**
> **理由：421 单独修是「白修」（AB 已证：422(b) 不做，攻击者边走 `agent="leader"` 仍拿 7 条权限）；
> 而 421 现网依赖 = 0、唯一 Leader 是显式注册、`caller=leader` 近 7 天仅 1 次且是 `dag_publish`（不走这条推断）。**
> **⇒ 它的真实风险 ≈ 「一个能调 `reserve_scope` 的攻击者，自称 `leader` 也能过」——
> 与 422 给的那 7 条权限是同一攻击者的同一能力，单独关 421 不减少任何实质风险。**

## 证据

### Q1：关掉整名后，现网**真实受影响**的是谁？⇒ **0 人**

#### Q1-a：`agents` 表 `role='Leader'` 的全部登记 = **1 条**

```
agents 表共 3 条:
  id=b2acdbf4c6cea9fe  type=server   role=Leader    first_seen=2026-10-23T16:01:17  status=active
  id=c335207187d95324  type=execute  role=Executor  first_seen=2026-10-25T08:03:47  status=active
  id=305ab0571c8193e8  type=execute  role=Executor  first_seen=2026-10-26T15:24:00  status=active

role=Leader 的条数: 1
```

#### Q1-b ⭐ 关键区分：那条 Leader **是靠什么拿到的**？

**反查指纹**（`fnv1a64("agent_id:" + raw)`，与 `server.mbt:455` 同算法，实测命中）：

```
目标指纹 b2acdbf4c6cea9fe
  ★ MATCH: "fist-mbt"
```

**⇒ 唯一 Leader 的原始名是 `fist-mbt`。**

**用旧推断规则跑一遍**：

```python
a = "fist-mbt".lower()
'commander' in a or 'human_steward' in a or a == "human"       → False
'leader' in a or 'lead' in a or 'polish' in a or 'optimization' in a  → False
⇒ 旧推断结果 = **Executor**
```

**但它 `agents.role = Leader`。**

**⇒ 结论：它是靠**显式注册**（`agents_register(role="Leader")`）拿到的，不是名字推断。**
**⇒ 关掉整名推断对它**零影响**。**

#### Q1-c：`memory/` `reports/` 里有没有真实（非叙述）的 `leader`/`lead` 整名 agent？

- Lane AB 已核：`memory/` 里 `lead` 62 处全是文档叙述
- **`call_log` 实测**：`caller='leader'` 出现过 **5 次**，但——

```
seq=114  ts=2026-10-11T13:15:19  tool=publish
seq=222  ts=2026-10-11T14:01:02  tool=publish
seq=223  ts=2026-10-11T14:01:12  tool=publish_parallel
seq=292  ts=2026-10-16T14:50:18  tool=publish
seq=351  ts=2026-10-21T01:55:37  tool=dag_publish
```

**⇒ 三点判读：**
1. **全部是 `publish`/`publish_parallel`/`dag_publish`** —— 这些走 **human_steward 特权路径**，**不经过 `infer_role_from_agent`**
2. **最近一次是 10-21**，`2026-10-20` 起仅 **1 次**
3. **没有任何一次是 `reserve_scope`/`reserve_try_set`** —— 也就是**唯一会用推断的那条路，从没被 `leader` 走通过**

#### Q1-d ⭐ 补核（原 R1）：那 5 次**本身就只有 1 次成功**

```
$ call_log 有 ok 列，实测：
seq=114  2026-10-11T13:15:19  tool=publish           ok=0   ← 失败
seq=222  2026-10-11T14:01:02  tool=publish           ok=0   ← 失败
seq=223  2026-10-11T14:01:12  tool=publish_parallel  ok=1   ← 唯一成功
seq=292  2026-10-16T14:50:18  tool=publish           ok=0   ← 失败
seq=351  2026-10-21T01:55:37  tool=dag_publish       ok=0   ← 失败
```

**⇒ 5 次里 4 次失败、1 次成功。**
**⇒ 这让「现网依赖 = 0」的结论**更强**：不只「走的不是推断那条路」，而是
**连它走的那条路（publish 特权面）都基本没走通**。**

**⇒ Q1 结论：关掉整名，现网真实受影响 = 0 人。**

### Q2：关掉后「军官自报」通道没了，谁能补上？

#### Q2-a：现在有谁真的在用「自报 `leader` 拿 Leader」这条路？

**⇒ 没有。** 证据见 Q1-c：`caller=leader` 的 5 次全是 `publish` 族（human_steward 面），
**从不经过 `infer_role_from_agent`**；`reserve_scope` 调用的 `agent` 参数在 `call_log` 里无 `leader` 记录。

**agent 名清单：空。**

#### Q2-b：若关掉，重获 Leader 的唯一路径是什么？**要走几步？**

**唯一路径 = `agents_register(agent_id="<fp>", role="Leader", ...)`**

**实测其可达性**：
```
$ grep -c "agents_register" src/server/server.mbt
1        ← 仅 1 处，且是 server 启动时的内部调用（server.mbt:632）

⇒ **`agents_register` 没有暴露成 MCP 工具**（MCP 工具清单里没有它）
⇒ 低权 agent **无法自助调用它**
```

**步数推算**：
| 方式 | 步数 | 需要谁介入 |
|---|---|---|
| 走 MCP 工具 | ❌ **当前不可能**（没这个工具） | — |
| human_steward 手工改库/调内部 API | **3+ 步** | **需要人** |
| 新增 MCP 工具面再调 | **要先开发** | **需要开发 + 人** |

**⚠️ 运维成本明确写出**：
> **关掉整名后，任何需要 Leader 级 `reserve_scope` 权限的新 lane，
> 都必须由 human_steward 介入注册（当前无自助面）。**
> **⇒ 成本 = 「每次新增 Leader 级 lane，你批一次」。**
> **但注意：现网**没有任何 lane 需要这条通道**（Q1-c），所以这个成本现在是 0，
> 只是「将来若出现」才会付。**

### Q3：第三方案逐条评审

| 方案 | 能否在现架构实现 | 动不动 schema | 动不动签名 | 动几个文件 | 新测试 |
|---|---|---|---|---|---|
| **(i) 名字与 `agents.role` 矛盾即报错** | ✅ **能** —— `engine_rsv.mbt` 已有 `agents_get`，加一次查表 + 矛盾判断 | ❌ 不动 | ❌ 不动（`resolve_agent_role` 已存在） | **2 个**（`engine_rsv.mbt` ×2 调用点 + `engine_scope_perm.mbt` 判断） | **3 格**（矛盾报错 / 一致放行 / 无登记走推断） |
| **(ii) 整名保留 + 首次使用需显式登记** | ⚠️ **要新建工具面** —— `agents_register` 未暴露 MCP | ❌ 不动 | ✅ **动**（新工具 + 可能加参数） | **3+ 个**（`server.mbt` 工具注册 + `engine.mbt` 透传 + 判据） | **2 格** |
| **(iii) 整名关掉 + 开放 Leader 自助登记** | ❌ **两件事都要做** = (i)/(ii) 的组合叠加 | ❌ 不动 | ✅ 动 | **4+ 个** | **4 格** |

**⚠️ (i) 的一个致命局限（必须说清）**：
> **(i) 只在「该 agent 有登记」时生效。**
> 但 `reserve_scope` **允许未登记的 agent 预订**（`engine_rsv.mbt:24-25` 的 `Unregistered` 档）——
> 攻击者只要**不登记**，就查不到 `agents.role`，**(i) 无从比较矛盾**，仍退回推断。
> **⇒ (i) 必须配合「未登记时不给 Leader」才有完整效果。**
> **而这正好等价于……关掉整名。** 所以 (i) 完整版 ≈ ①+③，工作量比「只做 ①」大。

**⇒ (i) 是「技术上最优」但不是「最省」** —— 若目标是「堵住越权口」，① 更省；若目标是「保留自助且正确」，③ 更对但要配套。

## 分析

### 为什么我建议「先不单独修」

**AB 的联动表我复核后成立**：

| 时序 | 整名白名单 | 查表 | 攻击者路径 | 拿到 |
|---|---|---|---|---|
| **只修 422(b)** | 开 | 开 | `agent="leader"` | **仍拿 7 条** |
| **只修 421** | 关 | 关 | `agent="<任意>` + 无障碍兜底 | **仍拿 7 条**（422 的兜底没修） |
| **两者都修** | 关 | 开 | 无 | **0 条** |

**⇒ 任一单独修都是白修。**

### 422 的 (b) 做了之后，421 的紧迫性怎么变？

| 422(b) 状态 | 421 的攻击面 | 421 紧迫性 |
|---|---|---|
| **未做（现在）** | 攻击者 can 不走整名、走 422 的兜底路径 | 🟡 **低** —— 421 不是主入口 |
| **做了** | 攻击者仅剩 `agent="leader"` 这条 | 🔴 **高** —— 421 成为**唯一入口**，必须同期关 |

**⇒ 结论：421 的紧迫性**由 422(b) 的进度决定**。正确顺序是「422(b) 与 421 同一笔」，
而不是「先修 421 再说」。**
