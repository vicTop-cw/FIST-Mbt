## 二、「单值写死」的可操作定义（本轮贡献）

任务书的初始定义是三条。实测后我把它细化成**可机检的 6 条**：

| # | 判据 | 说明 |
|---|---|---|
| **D1** | 字面量与变量比较 | `== "..."` / `!= "..."` / `.startswith("...")` / `.endswith("...")` / `x in ("a","b")` |
| **D2** | 字面量「像配置值」 | 含 `-` `_` `/` `.`，或长度 ≥ 6（排除 `"#"`、`""`、`"\n"` 这类） |
| **D3** | 不是协议字面量 | 排除扩展名（`.mbt`/`.py`/`.md`）、语言名（`moonbit`）、状态标签（`passed`/`failed`/`unknown`） |
| **D4** | 有真源副本 | 该值在**判据之外**也出现（说明它是「某处的真源值」而非私有约定） |
| **D5** | 非通用词汇 | 排除出现在 ≥30% 判据里的词（`__main__` / `source` 这类）——**这是 D4 的必须反店**，否则 `__main__` 会以 74 个「外部来源」冒充真源 |
| **D6** | **无自拒保护** | ← **这是决定「单值写死」成不成立的关键一条，任务书原定义里没有** |

### D6 为什么是决定性的

```
写死 + 无自拒  = 🔴 静默假绿（真源变了，判据比对新字面量，继续绿）
写死 + 有自拒  = 🟡 合理常量（真源变了，判据报 FATAL/红，人工改一次常量即可）
```

**实测中 11 条候选里 7 条因 D6 自动降级。** 若不加 D6，会交出一份 7 条假阳性的清单——
这正是本会话反复踩的「假阳性比假阴性贵」的镜像：**假阳性会消耗执行者的信任预算。**

## 三、实测数据（四道过滤的收敛过程）

```
[第 1 道] 66 份判据全扫，R1 比较形态命中              → 数千处
[第 2 道] + R2 像配置值 + R3 非常数                    → 208 条
[第 3 道] + R4 有外部真源 + R5 非通用词汇              →  98 条
[第 4 道] 分 H1 路径名 / H2 数值 / H3 版本串           →  11 条高危（H1）
```

| 类别 | 数量 | 性质 |
|---|---|---|
| H1 路径/文件名值写死 | **11** | 字面量是仓库真实文件名 ⇒ 改名后可能静默失效 |
| H2 数值真源写死 | 18 | **全部合理**：都是「反幻影下限」（`len(x) < 10` ⇒ FATAL），这是**正确做法** |
| H3 版本串写死 | **0** | 真源 `moon.mod version = 0.3.10`，无判据写死它 |

**H2 要特别说明**：18 条全是 `if len(real) < 40: FATAL 枚举器空转` 这种形状。
**这不是单值写死，而是「判据无法自证就拒绿」的自卫机制**，是全仓做得最对的一面。
若按初始定义把它们当缺陷报，就是 18 条假阳性。

## 五、变异实测（判例-50 遵守情况）

每次变异都先验证「变异真的改变了被测行为」，测完**无条件还原并核 hash**。

### M1 `moon.mod → moonx.mod`（真源改名）
```
基线   rc=0  PASS 本地包 import 存在性一致：26 份 moon.pkg 的 33 条本地 import …
变异生效 moon.mod 是否仍存在 = False（期望 False）✓
变异后 rc=2  FATAL 全仓 moon.pkg 里一条本地包 import 都没有 —— 判据空转，拒绝报绿
⇒ **判据感知到了**（rc 0→2）。自拒保护生效。
```

### M2 `CHANGELOG.md → CHANGELOGx.md`
```
基线   rc=0  … 历史面豁免 1 份（CHAN…）
变异后 rc=0  … 扫现状面 176 份，历史面豁免 1 份（CHAN…）
⇒ 判据 rc 未变，但**读数可解释**：CHANGELOG 是「豁免名单」成员，改名后
   它从 177→176（少扫一份），豁免数仍 1 —— 这不是静默假绿，是**豁免语义的正确表现**。
   （新文件默认**不**豁免 = 安全默认：万一有人新建历史账，会被当现状面严格比。）
```

### M3 `check_pkg_imports` 的 `MODULE`（**唯一曾判 🔴 的，实测后降级**）
```
P1 同一值两来源
   判据内写死 MODULE = 'vicTop-cw/fist-mbt'   (scripts/check_pkg_imports.py:46)
   真源        name   = 'vicTop-cw/fist-mbt'   (moon.mod:12)
   当前一致：True

P3 变异：MODULE → 'nonexistent-module/xyz'
   变异生效检查：文件里出现新值 → True ✓
   变异后 rc=2  FATAL 全仓 moon.pkg 里一条本地包 import 都没有 —— 判据空转，拒绝报绿
   ⇒ 判据感知到了。**我原先判它 🔴 是误判，实锤后降级 🟡。**
```

### 变异后的卫生检查（自曝一处操作瑕疵）

M3 还原后 `git status` 一度显示 ` M scripts/check_pkg_imports.py`。
**核实：三个 hash 完全一致**（工作区 / index / HEAD 均为 `9e81cdb4…`）⇒ 内容逐字节相同，
`M` 是我重写文件时的 **CRLF/LF 幻影**（本仓判例-集早有记录）。
已用 `git checkout -- <该文件>` 彻底清除，现 `git status` 该文件为空。
**教训：变异测试的还原不能只靠「内容相同」，要核 `git status` 干净，否则会给下一个 agent 留下一颗 M 幻影。**

### 6.2 建议的下一步（交统帅定，我不执行）

1. **补扫 6.1 第二行**（数值真源 = 某数）：这是最像 `DEFAULT_BUNDLE` 事故的形态，值得单独一轮。
   构造式：找 `== <N>` / `!= <N>` 且 N ∈ {跟踪文件数, 工具数, 测试数, 判据数, 章节数} 的当前真源值。
2. **把 §二 的 D1–D6 并入 `check_coverage_face.py`**：现有尺只管「清单型（1~10 条字符串序列）」，
   **D1–D6 是它的正交补充**，两者合起来才覆盖「硬编码」的两半。
3. **D6 应成为判据评审的必问项**：「这个写死值，真源变了会红吗？」——

### 6.3 本轮的一个方法论产出（建议入判例集）

> **判例-（建议号）：单值写死的判据比清单型隐蔽，但可被「自拒保护」免疫。**
> - 清单型：名单在代码里，肉眼可见「有没有漏」。
> - 单值型：一个 `if x == "foo"`，**你连"应该有几个值"都想不起来**。
> - **免疫方式**：让它**在真源取不到时报 FATAL 而不是继续比**。
> - 本仓 66 份判据里 11 条单值写死候选**全部因此免疫**（7 条显式自拒 + 4 条语义安全），
>   **说明「反幻影自拒」这条纪律已经从少数判据扩散成了全仓惯例**——这是本会话治理的正面成果，值得记下来。
