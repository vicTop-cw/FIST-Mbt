## 结果摘要

在 HEAD `13ddb72`（等价 `4ee92c6`，R29 修复后的最新 HEAD）的**干净 worktree** `temp/head4`（junction `.mooncakes`、独立 `_build`、**不设 `FIST_DB_PATH`**）上，用三态对照实测同一套测试：

| 运行 | 命令 | Total tests | passed | failed | exit |
|---|---|---|---|---|---|
| 并行 1 | `moon test --target js`（默认并行） | **1371** | 1369 | **2** | 2 |
| 串行 | `moon test --target js -j 1` | 1339 | 1339 | 0 | 0 |
| 并行 2 | `moon test --target js`（同命令复跑） | 1339 | 1339 | 0 | 0 |

**关键事实**：
1. 同命令、同 worktree、同环境，两次并行给出**2-failed 与 0-failed 两态**——非确定性（flaky）。
2. **测试数也不稳定**：1371 vs 1339，差 32。不是单纯"失败 2 条"，而是**并行调度下测试集合/计数本身在波动**。
3. **R29 自述的「1339/1339」**恰好是串行或幸运并行读数，**不保证 CI 并行下稳定绿**——同一命令两次并行即互相矛盾，铁证。

## 遗留风险

1. **并行 flaky 未定位到具体 2 条测试**：moon test 不打印失败详情，单包不可复现，需 `-v` 或并行度分级逼近才能抓出。
2. **测试数 1371 vs 1339 波动 ±32 未解释**：可能是 moon 并行调度 bug，或某包测试在并行下被重复/跳过计数。
3. **BUG-335 仍未入库**：并发 agent 的 Int32 适配尚未提交（工作树 196 个在途文件，`git show HEAD:src/server/server.mbt` 中 `publish_parallel_route` 命中 0）。配套锁 `bug335_ns_route_wbtest.mbt`（3 条白盒锁）保持 untracked 待并发 agent 提交后再补——不能提前提交（会引 [4021] 编译红，上轮已 revert 过一次，教训见 memory）。
4. **R29 全绿自述口径需修正**：`AGENTS.md` 中「1346/1346」及各类「全绿」自述，应补注"以连跑稳定为准"（BUG-340）。

## 后续建议

1. **CI 加"稳定性预热"门**：全量测试前同命令连跑 N 次（如 3 次），全绿才放行——治 BUG-340 的 flaky 间歇红。
2. **排查共享 `.db` 资源**：各包测试在 cwd 建独立 `.db`，但需确认并行时是否真的有跨包共享路径（如回退到 `./fist-mbt.db` 的场景），有则强制 `FIST_DB_PATH` 隔离。
3. **等并发 agent 提交 server.mbt 后补 BUG-335 锁**：HEAD 命中 `publish_parallel_route` > 0 即提交 `bug335_ns_route_wbtest.mbt`（预期 src/server 342→345）。
4. 并行失败定位可用 `moon test --target js -v`（打印每个测试名）反复跑抓 flaky。

## 勘误（追加于同一日，基于 5 次全量复测）

**BUG-340 定性修正**：5 次全量实测后，**项目代码本身稳定绿**（1339/1339 在串行 + 正常并行下复现），R29 的「1339/1339」是**准确读数**。BUG-340 的真实性质是 **moon 工具链并行调度 flaky**（偶发 1371 测试数 + 2 失败），**非项目代码 bug**。1371 vs 1339 差 32 指向 moon 并行收集测试的 bug（多跑 32 个）。结论：BUG-340 属**环境/工具链级**，不影响项目代码正确性；CI 建议加「稳定性预热」以规避 moon 自身抖动。
