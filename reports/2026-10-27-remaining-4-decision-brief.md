## BUG-388（medium）`moon fmt --check` 本机跑不完

**现状**：`moon 0.1.20261016` + Windows 上 `moon fmt --check` 报
`_build/wasm-gc/release/format/<file>: No such file` + `fatal: cannot hash`，**rc=-1**。
**对照实验**：本仓无关的 **3 文件最小工程同样复现** ⇒ **工具链缺陷，不是本仓问题**。
同版本 `moon fmt`（写模式）rc=0 正常。

**现状替代**：`scripts/check_fmt_gate.py` 已落地，rc 契约 `0` 干净 / `2` 不可测 / `1` 真差异
—— 本机恒 `DEGRADED(2)`，格式门权威面**以 CI（Linux nightly）为准**。

### 选项

| 选项 | 代价 |
|---|---|
| **A（建议）** 关门为「已知边界」 | 零成本。理由：判据已存在且诚实报 DEGRADED，CI 有真门。留着 OPEN 只是持续消耗注意力 |
| B 升级 moon 到修好的版本 | 需要验证新版对 `is` 模式匹配（d799f56 适配引入）的兼容性，可能引发大批迁移 |
| C 自己实现 format 判据 | 越界（在造工具链） |

**建议 A**：在账本抬头改 `FALSE_POSITIVE`（附「外部工具链边界 + 有替代判据」的立据），
并在 `AI-DEVELOPMENT-STANDARD.md` §7「已知边界」保留一行。

## BUG-420（high）ns 字段只是标签，不是落库位置

**现状**：`fist-mbt.db`（主库）有 **2432 条任务、63 种 ns 标签**，而各 ns 独立库多为 **0 条**
⇒ 按 ns 路由的工具（`get`/`list`/`archive`）对它们**一律 not found**。
**已落地**：C 案（止血 + 可诊断）—— `store_open` 回执 `warning`（148 vs 0 实测）、
`get`/`archive` 诊断式错误文案、`get(resolve_from_main=true)` 只读回落。7 格锁 + 变异对照。

### 选项

| 选项 | 代价 | 风险 |
|---|---|---|
| **A（读取侧回落 + 按 ns 过滤）** | 中等：改 `get`/`list` 的解析路径，加「主库回落 + ns 字段核对」 | ⚠️ **隔离语义变松**：兜底会让 A ns 客户端查到 B ns 数据（如果它知道 id）。**这是需要你拍的语义决定** |
| **B（迁移 2271 条到各 ns 库）** | 高：一次性搬迁 + 幂等 + 失败回滚 | ⚠️ 破坏性；搬到一半失败会留双写/丢失。**必须有备份 + dry-run** |
| **C（就停在 C 案）** | 零 | 每次 `store_open` 都会把 148 vs 0 摆到眼前；调用方知道要去掉 namespace 参数。**功能可用，只是不优雅** |

**建议**：**短期 C（现状即止）+ 中期 A**。理由：
- A 案的真问题是**隔离承诺**（多租户到底是不是安全边界？）。若只是「组织手段」⇒ A 案无害；
  若是**安全边界**⇒ A 案等于破边界，只能走 B 案。
- **这个判断我替不了你**：取决于你打算怎么用多租户。

**若选 A**：我可以在 1 轮内做完（`get`/`list` 的回落 + `resolved_from` 标注 + 回归锁）。
**若选 B**：需要先做一次只读盘点（已有 `temp/audit/lane_w_ns_census.py` 的普查数据）+ dry-run。

## BUG-428（high）部署产物陈旧但版本守卫 PASS

**现状**：`check_deployment_freshness.py`（42 格自检 + 5 处变异对照）已落地，实测报 **3 面 FAIL**：

| 面 | mtime | 内容面 |
|---|---|---|
| PATH 垫片 → `_build/.../cli.js` | 01:19 | 3/3（新鲜，WARN 级） |
| **部署副本** `%LOCALAPPDATA%/FIST-Mbt/fist-mbt.js` | 10-26 11:59 | **2/3** |
| **仓内快照** `dist/fist-mbt.js` | 10-24 06:16 | **1/3** |
| **release 产物** `_release/js/fist-mbt.js` | 10-18 16:34 | **1/3** |

**正在做**：`dist/` 刷新（`refresh_dist.py`，release 构建 + ESM shim 注入 + 自证）。
**刷完之后**：`dist` 面转绿，但**部署副本与 `_release` 两面仍旧**（那是「装到机器上」与「上一次 release」的事）。

### 选项

| 选项 | 代价 |
|---|---|
| **A（建议）** 刷 `dist/` + 重装部署副本 + 重打 `_release` | 中：`dist` 刷一次（5MB diff）、部署副本走安装流程重装、`_release` 用 release 流程重建 |
| **B** 只刷 `dist/`（正在做） | 小：`test_shim_handshake.py` 会测到新版；但另外两面仍会在判据里 FAIL |
| **C** 判据维持「诊断格」不追求转绿 | 零：`run_guards` 里它已是 `tolerant((0,1,2))` 诊断格，不挡门禁 |

**建议 A（分步）**：本轮刷 `dist/`；部署副本你重装一次（或告诉我装哪）；`_release` 留给下次 release 流程。

**⚠️ 关键约束**：**刷 `dist` 必须用已提交的稳定源码** —— 我等到 `engine/*` 的 WIP 被提交后才跑，
否则会把未完成的改动打进发布快照。

## BUG-430（high）MCP 工具面零认证

**现状**：**所有 agent 身份参数都是调用方可自报的字符串**。
- `agents.pubkey_fp` **全仓恒空**（BUG-403/404 的死承诺）
- `current_pid_token()` 是 `@env.now()/1000 % 2e9` 的**伪 pid**（同秒启动两进程会撞值）
- 无会话层

**已收口的（同族但不同面）**：
- BUG-418/421/422：**名字不再能提权**（子串/整名单词白名单全删）
- BUG-423/424：注册面毒化 + 锁权限门
- BUG-432：`claim` 的 RANK_GATE 改成 `role → rank`（名字不再参与授权裁决）
- BUG-436：ACL 判定身份收敛为单一真源

**⚠️ 但这些都只是「一致性」，不是「认证」** —— 本轮**没有**、也不该被理解为加强了安全强度。

### 选项

| 选项 | 代价 | 性质 |
|---|---|---|
| **A（真收口）** 引入会话令牌 或 `pubkey_fp` 签名 | **大**：MCP 面加认证层、连接期交换令牌、所有写工具校验；客户端（DSH/atomcode/codearts/claude）全部要改 | **架构变更** |
| **B（折中）** 只对**破坏性/授权类**工具（`delete`/`archive`/`agent_acl_grant`/`reserve_scope`）要求「显式 token 参数」，其余照旧 | 中：改 4-6 个工具的签名 + 客户端适配 | **行为契约变更** |
| **C（建议）** 保持现状 + **把边界写进文档**（`AI-DEVELOPMENT-STANDARD.md` §7 + AGENTS 判例） | 零 | 承认它是**协作式约定**不是安全边界 |

**建议 C（现在）+ 记 A 为长期方向**。理由：
- 这个工具的用户是**你自己的 AI agent**，不是敌对环境
- 真收口的成本（4 个客户端全改）远超收益（挡住的是「自己人」）
- **但必须在文档里写死**：「身份自报 = 已知边界」，否则下一个人会以为它是安全的
